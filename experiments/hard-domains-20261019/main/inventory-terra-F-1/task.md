Export replay({stock,operations}). stock maps known SKU strings to nonnegative integer on-hand units. Each operation has request_id, type and integer delivery time at (milliseconds). Holds are usable only while now is strictly below their expires_at; due active holds become expired before that receipt's command has an effect. No external clock is used.

Operations are reserve (reservation_id,sku,quantity,ttl_ms), cancel (reservation_id), commit (reservation_id), and adjust (sku,delta). An adjustment returns adjusted if resulting on-hand can still cover all active holds and is nonnegative; otherwise it returns rejected with no stock change.

request_id is a transport identity. Repeated request_id with the same command fields, excluding at, returns its original status even if the reservation has since expired or ended; it has no command effect and never reverses clock/expiry. Reusing request_id with different command fields throws an Error. Different request IDs are not duplicates merely because their quantities match.

reservation_id is a distinct business identity. Reserving an existing reservation with the same sku/quantity/ttl returns its current state without renewing expiry or allocating again; different terms throw an Error, even after it ends. Terminal states never resurrect. An unknown cancel records a cancelled tombstone: a later reserve with that ID returns cancelled and allocates nothing. Cancel/commit against a known terminal reservation returns that state without stock effects. Cancel/commit of an active reservation performs the named transition. Rejected/insufficient statuses and original request outcomes are also replayable.
