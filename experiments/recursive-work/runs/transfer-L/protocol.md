# MAGI 업무위임 검증 실행 명세

## 목적과 주장

사람이 같은 설명과 교정을 반복하지 않아도, 사용자가 목적과 제약을 맡기면 MAGI가 관련 업무를 등록하고, 필요한 작업을 분해하고, 실제 파일과 도구를 사용해 수행하며, 오류를 교정하고 결과를 근거와 함께 반환하는지 검증한다. 이번 실행으로 주장할 수 있는 범위는 로컬 SQLite 역할 메모리, tracker와 독립 checker, review/reopen/recertification, 실제 파일 생성이 존재한다는 점이다. 일반 자연어 계획 런타임, 일반 학습 효능, 토큰·인간 시간 절감, Hermes/Letta/OpenClaw 설치·벤치마크는 현재 구현 또는 입증 범위가 아니다.

## 구조와 책임

판단 주체는 현재 실행 agent다. 입력은 목적, 제약, 현재 근거(current-facts), 과거 경험의 관찰 요약, 실행 도구와 권한이다. agent는 기존 이슈를 먼저 조회하고 재사용하며, 없으면 child task를 등록한다. 출력은 실행 명세, 사례 데이터, 결과 요약, tracker의 완료 상태와 각 artifact SHA-256이다. 의존성은 Python tracker, state.json, 파일시스템, 독립 checker와 review 도구다. 저장·조회·출력·실제 작업효과를 별도로 관찰한다.

현재 구조는 역할 메모리 어댑터와 로컬 업무 tracker를 조합한 수동·도구 중심 실행이다. 목표 구조는 자연어 목적을 계약으로 해석하고, 관련 과거 경험을 제한적으로 검색하고, 새 과제를 전이 가능한 단위로 계획·실행·검증·교정하는 런타임이다. 후자는 목표이며 현재 구현으로 간주하지 않는다.

## 실행 절차와 판정

1. 목적을 읽고 기존 이슈의 범위와 상태를 조회한다. 중복이면 재사용하고, 필요한 경우에만 child protocol-cases를 등록한다.
2. 경험 과제와 전이 과제를 각각 실행한다. 전이 과제는 표면 ID, 문장, 파일 위치, 순서, 도메인 중 하나 이상을 바꾸고, 같은 답을 복사해 통과할 수 없게 한다.
3. agent가 만든 요청과 도구 응답을 calls.json에 보존한다. 실패도 삭제하지 않고 남긴 뒤 국소 수정하고 재실행한다.
4. 출력 파일의 내용, 구조, tracker 상태, 독립 검사 결과를 확인한다. 파일 존재와 SHA-256은 무결성 증거이지 의미적 정확성이나 실제 사용자 시간 절감 증거가 아니다.
5. acceptance를 충족하고 열린 child가 없을 때에만 artifact의 SHA-256을 evidence로 tracker에 완료 등록한다.

실제 도구행동은 (a) tracker에 이슈가 등록됐는가, (b) 파일이 실제 생성·수정됐는가, (c) 오류가 calls.json에 남았는가, (d) checker/review가 결과를 판정했는가로 구분한다. 설명만 생성한 경우 실행으로 판정하지 않는다.

## 비교군

G(경험 없음)는 현재 목적과 입력만 받고 과거 관찰을 제공하지 않는다. F(고정규칙)는 경험을 읽지 않고 미리 선언한 규칙과 템플릿만 적용한다. L(원문)은 과거 실행의 원문 전체를 그대로 제공하되 검색·요약·경계가 없다. E(추출교훈)는 관찰된 실패와 교정 원인만 제공한다. E의 기대는 문구 복사가 아니라, 새 사례에서 같은 원칙을 적용하고 다른 세부에 맞춰 산출물을 만드는 것이다.

각 군에서 같은 acceptance, 도구, 비용 측정을 사용한다. 성공률, 오류 재발률, 재분해 횟수, 호출 수와 토큰, 사람의 교정 횟수, artifact 및 실행 효과를 별도로 기록한다. 현재 실행은 이 비교의 실제 수치나 학습 효능을 아직 측정하지 않는다.

## 오류·교정·비용

실패한 요청과 응답을 보존하고, 원인을 입력 형식·중복·부모 관계·근거 해시·의미 오류로 분류한다. 수정은 실패한 경계에 국소 적용하며, 전체 목적을 임의로 바꾸지 않는다. 오류 후 재실행에서는 동일한 acceptance를 유지하고, 새 결과의 해시와 호출 수를 기록한다. 전체 비용은 모델 호출, 도구 호출, 재시도, 사람 교정 시간을 합산하되 현재 파일에는 측정값을 만들지 않는다.

## 반증·철회·재분해

다음이면 주장을 반증한 것으로 표시한다: 전이 과제에서 경험군이 G/F와 같은 복사 오류를 내거나, tracker가 열린 child·빈 evidence·순환 부모를 허용하거나, 실패 호출이 사라지거나, 독립 checker와 결과가 불일치하는 경우다. 잘못 추출된 교훈은 근거와 적용 범위를 표시해 철회하고, 기존 완료 task는 reopen 후 재검증한다. 입력 목적이 달라졌거나 acceptance가 충돌하면 과제를 다시 분해하고 새 child를 등록한다. 새 취향·가치·권한 변경만 인간 판단으로 남기며, 기존 목적 안의 기술 판단·검증·학습 채택·철회는 agent가 수행한다.

## 미측정 한계

이번 명세는 파일·tracker 수준의 실행을 정의한다. 실제 자연어 계획 런타임의 자동성, 장기 기억의 올바른 검색, 일반화 범위, 총 토큰 절감, 인간 시간 절감, 실제 장비 제어 효과, 제품 설치와 외부 서비스 연동은 측정하지 않는다. 따라서 이번 결과는 실행 가능한 검증 설계와 현재 도구의 일부 동작을 보여주지만 MAGI의 일반적 자율 학습을 입증하지 않는다.
