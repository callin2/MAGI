# MAGI 첫 실사용 구성 기술 결정 개정안

## 판정 범위

현재 확인된 구현은 `role_memory.py`와 관련 7개 시험, 현재 작업도구·독립판정기와 관련 17개 시험이다. 이번 문서 작성과 tracker 처리는 실제 실행된 업무다. 이 사실은 자연어 요청을 일반 계획으로 만드는 런타임이 완성됐다는 뜻이 아니다. 자연어→계획→실행 연결은 다음 구현을 위한 목표 구조로 결정한다.

## 추천 목표 구성

첫 실사용의 목표 구성은 작은 adapter, 기존 실행 도구, 파일/git 기반 지속 저장소, JSON 자료 계약이다. 책임은 다음처럼 나눈다.

| 단계 | 책임 | 입력 | 출력 | 현재 상태 |
|---|---|---|---|---|
| 1. 요청 정리 | adapter | 자연어 목적, 범위, 역할, 완료 조건 | 구조화된 작업 요청 | 목표 구조; 일반 자연어 런타임 미구현 |
| 2. 교훈 조회 | memory 계층 | 역할·프로젝트 ID, 구조화된 작업 요청 | 관련 교훈과 revision, 근거·적용 조건 | role memory 구현·7시험 통과; 일반 검색/전이 미검증 |
| 3. 계획 작성 | adapter | 요청, 교훈, 허용 도구 | 단계, 책임, 입력·출력, 검증 조건 | 목표 구조 |
| 4. 실행 | 기존 작업도구 | 승인된 계획과 허용 범위 | 파일 변경, 명령 결과, 로그 | 작업도구·독립판정기 구현·17시험 통과 |
| 5. 판정 | 독립판정기 | 산출물, hash, 시험·로그 | 통과/실패, 미검증 목록 | 현재 구현 범위에서 확인 |
| 6. 교훈 후보화 | 사람 승인 경계 | 결과, 교정, 원인 가설 | 승인·보류·철회 가능한 교훈 후보 | 목표 구조; 효과 미검증 |

실행 경로는 `자연어 요청 → 구조화 → 관련 교훈 조회 → 계획 → 사람 승인 범위의 작업도구 실행 → 독립판정 → 교훈 후보`다. 현재는 1·3을 일반 런타임으로 제공한다고 주장하지 않으며, 2·4·5의 확인된 구현을 1·3의 목표 경로에 연결하는 작업이 남아 있다.

## 선택 근거와 제외 범위

Hermes는 profile과 memory·세션 상태 분리, Letta는 정체성·대화·git versioning, OpenClaw는 절차 파일의 archive/restore를 설계 참고로만 사용한다. 세 제품을 설치하거나 성능을 비교한 결과가 아니다. 전체 런타임 도입, 자동 background 학습, 자기 코드 진화는 작은 첫 검증의 필수 범위가 아니므로 목표 구성에 포함하지 않는다.

## 검증 계획과 미검증

구현 후 같은 과제를 no-memory, 로그만, 승인된 lesson 조건으로 실행하고 재설명 횟수, 오류, 시간, 호출·토큰, 생성·검색 비용, 다른 과제로의 전이를 기록한다. 현재 시험 통과는 각 구현·도구의 시험 근거이며 자연어 계획의 일반성이나 교훈 전이 효과를 증명하지 않는다. 제품 설치·호환성, 세션 간 전이, 충돌·철회, 범용 학습 효과와 비용 절감은 미검증이다.
