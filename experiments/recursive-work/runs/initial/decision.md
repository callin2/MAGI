# MAGI 첫 실사용 구성 기술 결정

## 추천

첫 구성은 **작은 adapter + 기존 실행 도구 + 파일/git 기반 지속 저장소 + JSON 자료 계약**으로 한다. 사용자의 한국어 자연어 요청은 adapter가 작업 목적·범위·입출력·검증 조건으로 정리하고, 기존 실행 도구가 실제 작업을 수행한다. 실행 결과와 교정은 원인 가설·관측 사실·후속 검증으로 나누어 기록하고, 다음 세션에는 현재 역할·프로젝트 범위와 일치하는 교훈만 읽는다.

Hermes·Letta·OpenClaw의 전체 제품 런타임은 첫 구성에서 제외한다. 대신 profile과 실행 상태의 분리(Hermes), 정체성·대화·git 버전의 분리(Letta), 절차 파일의 archive/restore(OpenClaw)를 adapter의 최소 계약으로 가져온다. 이는 설치·성능·학습 효과를 확인했다는 뜻이 아니다.

## 실행 경로와 계약

`사용자 요청 → adapter(목적/범위/역할/입력/출력/검증) → 관련 교훈 조회 → 기존 실행 도구 → 결과·로그·diff → 검증 → 승인된 교훈 후보/보류 → 다음 세션 snapshot`

adapter의 입력은 자연어 요청, 역할·프로젝트 식별자, 허용 범위, 검증 요구다. 출력은 실행 계획, 호출 대상, 산출물 경로, 검증 결과, 미검증 항목이다. 지속 저장소는 JSON 계약과 git revision을 사용하며 각 교훈 후보에 원본 관측·적용 조건·반증 조건을 연결한다. 기존 실행 도구는 실제 파일·명령·검증을 담당하고 adapter는 판단 경계와 기록을 담당한다.

의존성은 현재 실행 도구, 파일 저장소, git, JSON parser다. 외부 서비스 로그인이나 별도 제품 설치는 필수 의존성으로 만들지 않는다. 역할별 파일과 프로젝트 범위를 명시하고 충돌 시 자동 승격하지 않으며, 잘못된 교훈은 archive/restore 또는 보류로 즉시 되돌릴 수 있어야 한다.

## 선택·제외 이유

이 구성이 선택된 이유는 현재 자료에서 이미 확인된 지속 파일, git 버전 관리, JSON 계약, 기존 실행 능력을 재사용하면서 추가 구현을 근거 연결·범위·철회·효과 측정으로 제한하기 때문이다. Hermes는 profile과 memory 구분을, Letta는 정체성과 버전·reflection을, OpenClaw는 절차 수정과 archive를 각각 참고한다. ACE의 국소 교정 패턴도 참고할 수 있지만 UPDATE/MERGE/DELETE가 TODO인 소스 상태를 완성된 철회 기능으로 간주하지 않는다. DGM식 자기 코드 진화는 이번 역할 경험 전이 범위에 필요하지 않아 제외한다.

## 검증과 미검증

같은 과제를 no-memory, 로그만, 승인된 lesson 포함 조건에서 반복한다. 재설명 횟수·동일 오류·완료 시간·모델 호출·토큰·생성/검색 비용과 별도 과제 전이 결과를 기록한다. 적용 전후의 실제 파일 diff와 검증 로그를 확인하고, 실패 교훈도 보존한다. 비용을 재지 않으면 비용 절감이나 토큰 효율을 주장하지 않는다.

현재 미검증은 adapter의 실제 구현·실행, 세션 간 교훈 전이, 역할 충돌·철회, Hermes/Letta/OpenClaw 설치와 호환성, 범용 학습 효과, 수치 우월성이다. 제공 자료에는 MAGI 직접 시험(M)이 없으므로 이 문서는 기술 결정과 검증 설계이지 실험 결과 보고서가 아니다.
