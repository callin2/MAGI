# 독립 분해 판단 C

## 1. 가장 작고 유용한 사용자 산출물

가장 작은 유용한 결과는 사용자의 한 업무 목표를 입력으로 받아, 실제 검토 가능한 최종 결과물과 짧은 실행 증적을 함께 내놓는 MAGI 수직 파일럿이다. 역할 분해 JSON이나 에이전트 로그가 목적이 아니다. 사용자가 읽고 다음 행동을 결정할 수 있는 한국어 결과 문서가 중심이며, 문서에는 목표, 완료 기준, 선택된 결과, 근거, 미확인 사항, 검증 결과, 재현 방법을 포함한다. 기존 `role_memory.py`는 역할과 상태, 후보 및 검증·철회, scope/grant, revision 영수증을 기록하는 기반으로 재사용한다. 성공은 코드가 생긴 것이 아니라 목적에서 실제 완성 산출물까지 도달하고, 신뢰할 수 있는 부분과 보류해야 할 부분을 사용자가 구별할 수 있는 것이다.

## 2. 경쟁 분해안과 선택

경쟁안 A는 요구사항 분석, 조사·초안, 비평·검증을 각각 병렬로 나누는 역할 중심 DAG다. 독립 판단을 확보하기 쉽지만 작은 업무에서도 조정 호출과 형식 비용이 커지고, 실제 사용자 가치보다 프레임워크 산출물이 커질 위험이 있다.

경쟁안 B는 산출물 중심의 순차 수직 슬라이스다. 먼저 목표와 완료 계약을 고정하고, 판단이 필요한 부분만 2개의 독립 결과안으로 나눈 다음 통합·검증해 최종 문서를 만든다. 반복 실패가 확인된 leaf만 재분해한다. 이번 파일럿은 B를 선택한다. 현재 해결할 문제는 새 일반 엔진이 아니라 실제 목적→결과 연결의 부재이므로, 기존 자료와 subagent 협업을 이용해 짧은 경로로 결과를 완결해야 한다. A의 병렬 독립성은 충돌 가능성이 높은 판단 지점에만 국소적으로 적용한다.

## 3. 실행 leaf

첫 leaf는 `목표·완료 계약`이다. 입력은 사용자 원문과 제약, 출력은 목적·대상 사용자·산출물 형식·검증 가능한 완료 기준·금지 범위·검토 질문이다. 의존성은 없고, 원문 요구와 새 가정을 분리하며 모든 기준이 검사 가능한지 완료 검사한다.

둘째 leaf는 `독립 결과안`이다. 두 실행 주체가 계약만 보고 각각 결과 초안, 근거, 불확실성, 예상 실패를 작성한다. 서로의 답은 보지 않는다. 각 안이 기준을 모두 다루고 실제 사용자 내용과 추정을 구분하는지 검사한다. 이미 명확한 수행까지 3개 에이전트로 강제하지 않는다.

셋째 leaf는 `통합·검증 패키지`다. 조정자가 계약과 두 안을 비교해 선택 이유, 최종 결과, 충돌, 검증 표, 미확인 항목, 재현 절차, 다음 과제를 작성한다. 원문 추적성, 사용자 열람 가능성, 독립안 차이, 검증과 미검증 주장 분리, revision 및 실행 증적 연결을 검사한다.

## 4. 통합·실패·재분해·중단

조정자는 계약 위반과 사실 불일치를 먼저 표시하고 공통점·충돌점·선택 근거를 기록한다. 입력 누락이나 형식 오류는 해당 leaf만 한 번 재실행한다. 완료 기준 해석이 충돌하면 계약을 보완하고 그 판단 지점만 재분해한다. 같은 실패가 두 번 반복되거나 필요한 자료·도구·권한이 없어 검증할 수 있으면 중단하고 필요한 결정이나 자료를 명시한다. 독립 호출 수가 늘어도 판단 독립성이 증가하지 않거나 통합 비용이 결과 가치보다 커지면 추가 분해를 멈춘다. 검증되지 않은 결과는 완료로 주장하지 않는다.

## 5. 경험과 다음 과제 전이

실행 뒤 조정자는 목표 유형, leaf별 입력·출력·책임, 재실행 횟수, 충돌, 통합 판단, 검증 결과, 유용했던 호출과 불필요했던 호출을 짧은 회고로 남긴다. `role_memory.py`에는 검증된 사실과 제안·가설을 분리해 scope와 revision을 붙여 저장한다. 기억은 다음 실행의 정답 주입이 아니라 분해 제안과 비교 자료로 사용한다. 다음 과제는 반복 병목 하나만 선택한다. 계약 누락이 반복되면 계약을 보완하고, 독립안이 늘 같으면 독립 실행 조건을 줄이며, 통합이 병목이면 충돌 표현과 검증 체크를 개선한다. 이렇게 기록해야 다음 작업이 새 프레임워크 개발이 아니라 사용자 결과와 실제 경험의 개선으로 이어진다.
