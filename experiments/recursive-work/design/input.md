# 독립 MAGI 분해 판단

목표: 경험에서 나아지는 에이전트 협업을 통해 인간의 반복 설명·교정·판단 부담을 줄이고 실제 지적노동을 맡긴다. 사용자 승인: 한번에 끝내기 어려우면 MAGI로 분해 가설을 비교하고 하위 작업에도 같은 원칙을 재귀 적용한다. 사용자에게 매 단계 계속 여부를 묻지 않고 실행·통합·검증·재분해를 이어간다.

지금 수행할 실제 과제: MAGI 저장소에 사용자가 목표를 주면 그 목표를 하위 책임·실행·통합·검증으로 이어가 검토 가능한 결과를 얻는 작은 실행 파일럿을 만들어라. 제품 전체를 새로 만들지 말고 기존 자료와 코드를 재사용해 유용한 수직 범위를 하나 완결한다. 코드를 만드는 것 자체가 목표가 되면 안 되며 구체 사용자 결과(목적→실제 완성 산출물)를 제시하라.

현 저장소: Python 표준 라이브러리만 사용하는 연구 저장소. role_memory.py는 SQLite JSON CLI로 역할·state/binding·후보·검증/철회·scope/grant·revision 영수증을 제공. 7개 실패 지향 시험 통과. 모델 API 런타임은 없으며 collaboration subagents로 실제 판단은 가능. 단순 합성 기억 실험만 했고 의미상8/8이지만 교훈 없어도 같은 답, 토큰 미노출로 효율 미입증. 기존 문서에는 평가 계약·독립성·의사결정 수명주기·기억 계약이 있다. 지금은 이슈와 보고서만 늘리고 사용자에게 실제 검토 가능한 업무 결과를 주지 못했다는 문제가 중요하다.

판단 A/B/C는 서로 의견을 모른다. 같은 입력만 읽고 다른 파일/웹 읽기나 쓰기·이슈·중앙보고는 하지 않는다. 출력은 한국어 1500~2500자로: (1) 가장 작고 유용한 사용자 산출물, (2) 2개 이상 분해 경쟁안과 선택 이유, (3) 실행할 leaf 2~3개와 책임/입출력/의존성/완료 검사, (4) 통합·실패/재분해/중단 기준, (5) 실제 경험과 다음 과제 전이를 남기는 방법. 꼭 3에이전트를 모든 작은 leaf에 강제하지 않는다. 독립 판단은 중요한 미해결 분해/충돌에 쓰고 이미 명확한 수행은 바로 실행한다. 정해진 형식 작업만 하는 새 프레임워크·대형 서비스 도입을 필수로 만들지 않는다. 새 가치 판단은 보류하고 합의된 목표 아래 기술 선택은 진행한다. 조정자가 전원 완료 뒤 원문과 조정을 기록한다.
