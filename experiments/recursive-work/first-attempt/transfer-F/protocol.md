# MAGI 업무위임 검증 실행 명세

## 목적과 주장

사람이 같은 설명·교정을 반복하지 않아도 목적과 제약을 전달받은 MAGI가 실제 산출물과 작업 상태를 만들고, 오류를 교정하며 새 과제로 전이하는지 검증한다. 이번 명세가 검증할 수 있는 주장은 SQLite 역할 메모리 어댑터, 로컬 tracker, 독립 checker, review HTML, 파일 생성과 tracker 완료·재개·재인증 흐름을 하나의 실행 절차로 평가할 수 있다는 것이다. 일반 자연어 계획 런타임, 일반 학습효과, 토큰 절감, 사람 시간 절감은 현재 구현으로 입증하지 않는다.

## 현재 구현과 목표 구조

현재 근거는 `current-facts.json`의 7개 메모리 어댑터 테스트와 19개 tracker/checker/review 테스트, 실제 파일 생성·완료·review/reopen/recertification 실행이다. 목표 구조는 목적과 완료조건을 먼저 이슈에 등록하고, 경험을 검색해도 원문 정답을 복사하지 않은 상태에서 MAGI가 입력을 해석하고, 도구를 호출해 파일과 상태를 만들며, 독립 검증기가 결과·해시·상태 전이를 판정하고, 실패 시 원인을 기록해 재실행하는 구조다. 목표 구조의 자연어 계획과 전이 일반화는 아직 미구현·미검증이다.

## 실행 책임, 입출력, 의존성

판단 주체는 MAGI다. 입력은 목적, 제약, 현재 사실, 경험의 규칙 요약, 새 사례의 비밀 acceptance 기준이다. 출력은 `protocol.md`, `cases.json`, 실행 로그(`calls.json`), tracker 상태와 완료 증거다. 의존성은 SQLite 역할 메모리 어댑터, tracker CLI, 독립 checker, review HTML, SHA-256 계산기다. 사람은 새 취향·가치·권한 변경만 결정하고, 이미 합의된 목적·제약 안의 채택·철회·재분해는 MAGI가 결정한다.

각 사례는 (1) 관련 기존 이슈 조회, (2) 없으면 child 이슈 등록, (3) 경험 없이 기준선 실행, (4) 허용된 경험을 적용한 실행, (5) 별도 전이 입력 실행, (6) 파일 내용·도구 호출·tracker 상태를 독립 검증, (7) 실패면 국소 교정 후 재실행 순서다. 입력에는 예상 정답, 채점키, 다른 실행 결과를 넣지 않는다.

## 경험 조건 비교

| 조건 | 제공 정보 | 판정 의미 |
|---|---|---|
| G (경험 없음) | 목적·제약·현재 사실만 | 설명 반복 없이 기준선 수행 가능한가 |
| F (고정규칙) | `fixed-runbook`: 기존 작업 확인, 목표·완료조건 정의, 산출물·증거로 완료 | 규칙을 적용해 누락과 미완료 주장을 줄이는가 |
| L (원문) | 과거 사례의 원문·예상 결과를 직접 제공하지 않음 | 원문 복사가 아닌 실행 규칙 사용 여부 |
| E (추출교훈) | fixed-runbook의 일반화된 규칙 요약 | 다른 도메인·식별자로 규칙을 전이하는가 |

F와 E는 동일한 사례의 답을 재사용하는 조건이 아니다. 경험 입력은 절차적 규칙만 포함하고, 사례별 목표·식별자·오류·acceptance는 매번 새로 만든다.

## 실제 도구행동 판정

성공은 텍스트가 그럴듯한지로 판단하지 않는다. `calls.json`에 실제 요청과 응답이 남아 있고, 필요한 파일이 생성되며, tracker가 올바른 issue와 evidence를 가진 상태로 완료되어야 한다. 독립 checker는 파일 존재, JSON schema, 필수 가족·전이 수, SHA-256과 tracker evidence의 일치를 확인한다. 도구 오류는 숨기지 않고 원문 응답을 남긴 뒤 허용 범위에서 요청 형식만 고쳐 재실행한다.

## 오류·교정·전체 비용

각 시도마다 요청, 응답, 오류 종류, 교정 이유, 재시도 횟수와 토큰·시간·도구 호출 수를 기록한다. 오류가 나면 원인을 입력 형식, 산출물 내용, 상태 전이, 독립 검증 중 하나로 분류하고 한 국소 수정만 적용한다. 세 번 연속 같은 원인으로 실패하면 해당 사례를 미완료로 표시하고 재분해한다. 전체 비용은 G/F/E 각각의 모델 호출 수, 도구 호출 수, 재시도 수, 경과시간, 산출물 검증 통과 여부의 합으로 보고한다. 비용이 측정되지 않은 실행은 효율성 주장을 하지 않는다.

## 반증·철회·재분해

다음 중 하나면 주장을 반증하거나 해당 경험을 철회한다: 예상 정답 유출이 발견됨, 실제 도구 호출 없이 결과만 생성됨, tracker 상태와 파일 증거가 불일치함, 독립 checker가 실패함, 전이 사례에서 원래 식별자만 치환했음, 또는 같은 오류가 세 번 반복됨. 철회 시 해당 경험을 입력에서 제거하고 G 조건으로 재실행한다. 목적·권한·완료 기준이 바뀌었거나 사례가 단일 기능에 과도하게 의존하면 새 child 이슈로 재분해한다.

## 미측정 한계

현재는 세 가족의 소규모 사례와 로컬 실행만 다룬다. 실제 자연어 계획의 범용성, 장기 기억의 정확도, 다중 사용자 권한, 제품 Hermes/Letta/OpenClaw와의 비교, 물리 장치 효과, 총 토큰·사람 시간 절감은 측정하지 않는다. 따라서 이번 결과는 실행 명세와 제한된 전이 검증의 근거이지 일반 학습능력의 증명이 아니다.
