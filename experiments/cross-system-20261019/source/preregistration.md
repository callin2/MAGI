## Independent behavioral judgment

The coordinator-only judge runs the actual candidate module/CLI, using fixtures and assertions rather than model self-ratings or patch-text matching. It is frozen before scored outcomes. It checks:

- Repair: missing/tampered source, missing/failed holdout, unsupported holdout success phrase, failed/missing process capture exit, omitted evidence argument and truthy nonboolean report claims cannot establish success.
- Counterexamples: a valid clarification and a valid answer, with no candidate file, still complete; finalCandidate/fixedHoldoutPass remain false. Blindly imposing nonempty tracker evidence or requiring a file for every complete state is a wrong analogy.
- Regressions: valid candidate and mixed conversations pass; compiler pin, turn counts, response-kind mismatches/duplication, saved/final digests and report process/check failures remain enforced.
- Real CLI integration: valid case files succeed; tampered source and missing holdout fail; an existing verdict is preserved without partial summary overwrite.

The real unmodified historical defect must fail repair/integration criteria; the real unmodified upstream fixed version must pass all. These are deterministic calibration controls, not LLM results. Fixtures contain synthetic source bytes and captures to test real code; they are not fabricated model responses. The source/artifacts are never executed as product programs.

Worker tests run with Node permission restrictions, allowlisted workspace reads/writes, no network, child processes, addons or workers, and a minimal environment without credentials. Hidden module and CLI evaluation likewise uses restricted Node subprocesses and fresh temporary fixture directories. Only the controller reads existing model credentials.

Full success requires all hidden criteria, valid deliverable.json exactly {schema_version:1,summary:string,tests_run:string[],limitations:string[]}, nonempty notes.md and candidate.test.mjs, and evidence of a successful tests-tool call. Report repair success, regressions, counterexamples and integration separately. Wrong-analogy score is behavioral counterexample failure; a note claiming insight is not proof of causal reasoning. Schema/format failures are distinguished from actual module behavior.

## Limits, observations and interpretation

Reuse prior runner bounds: 16 model calls, 60 tool calls, 300 seconds per conversation, max output 8192 tokens per call. No conversational retries, compression, outcome replacement or human correction prompts. A 401/403 stops the batch immediately; other provider errors are preserved and two consecutive transport failures stop remaining runs. Never silently retry uncertain outcomes; inspect events/execution first. Frozen records refuse overwrite.

Measure actual code success, new regressions, wrong analogy, model/tool calls and errors, elapsed time and provider-reported token fields. Adaptation cost is an operational proxy (calls/time/tokens), not directly observed cognitive work. Record user corrections as zero under this no-intervention protocol, not as time saved. Cash prices, original experience creation, coordinator usage and human time remain unknown. Infrastructure blocks/unrun cases are not scored as task failures or successes. With only two repetitions per arm and one target, any future difference is exploratory; no significance, broad generalization or MAGI-wide benefit claim.

If an oracle error is found, preserve the old judgment and disclose affected comparisons rather than changing criteria to favor outcomes. Publish progress, failure, immutable sources and results on a review branch; do not merge main, deploy, alter auth, or update the original target repository.
