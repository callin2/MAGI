가장 먼저 입증해야 할 주장은 “경험을 정제해 역할에 맞게 저장·검색하면, 같은 작업을 다시 수행할 때 실제 행동의 성공률이나 완료 효율이 개선되고 그 개선이 다른 세션의 과제에도 전이된다”이다. 현재 자료는 지속 조회 경로와 계약·권한·철회 동작이 작동한다는 점은 보여주지만, 이 주장을 입증하지는 않는다. 원문 로그가 8/8, 정제 교훈이 엄격 기준 5/8(보조 진단 8/8), 기억 없음이 3/8인 결과는 정제 교훈의 독립적 우월성을 보여주지 않는다. 반복 2회와 합성 사례만으로 장기 학습이나 토큰 절감을 결론 내릴 수도 없다. 검토 합의와 구현 시험 통과는 효과의 증거가 아니다.

경쟁 설명은 적어도 다음처럼 분리해야 한다.

1. 성과가 좋아진다면 그것은 정제된 경험의 효과가 아니라 원문 로그가 제공한 정보량, 고정 출력 지침, 사전 계약, 모델의 일반 추론, 혹은 동일 사례의 반복 노출 때문일 수 있다.
2. 경험 저장 시스템이 없어도 모델은 pagination이나 continue 같은 판단을 기초 지식으로 수행할 수 있다. 실제로 교훈 제외·철회 대조에서 같은 결론을 냈다는 점은 이 설명을 지지한다.
3. 성과가 좋아 보여도 기억 자체의 효과가 아니라 역할화, 다중 검토, 조정자의 source 대조, 후속 검증 호출이 만든 효과일 수 있다.
4. 개선이 있다면 정확도보다 출력 형식 준수나 재설명 감소만 나타날 수 있으며, 이것이 실제 업무 완료나 인간 시간 절감으로 이어진다는 보장은 없다.

따라서 최소 성공 기준은 “저장된 경험이 존재한다”가 아니라 사전 고정된 동일 스키마를 사용한 여러 독립 과제에서 실제 행동 결과가 개선되는 것이다. 각 조건은 no-memory, 원문 로그, 정제 교훈, 교훈 제외, 오염된 교훈, 철회된 교훈으로 나누고, 입력 정보량과 출력 형식을 맞춰야 한다. 최소한 학습 과제와 별도 전이 과제를 분리하며, 전이 과제는 다른 식별자·작업·상태를 사용해야 한다. 같은 과제를 재설명하는 것만으로는 전이를 입증할 수 없다.

필요한 계측은 다음 네 층을 구분해야 한다. 첫째, 판단 정확도와 형식 준수: 기계 판독 스키마, 누락·중첩·오형식 검증기를 실행 전에 고정하고 모든 조건에 동일 적용한다. 둘째, 실제 행동: 후속 이슈 등록, 중복 확인, 재설명 요청, 파일·도구 적용, 완료·회복 여부를 관찰한다. JSON 응답이나 adapter 영수증만으로 외부 업무 완료를 주장하지 않는다. 셋째, 인간 부담: 사용자의 설명 횟수, 재검토 시간, 수정 횟수, 승인·거부 부담을 실제 시간 또는 명시된 관측값으로 기록한다. `need_clarification` 출력 수는 인간의 설명 횟수나 시간 절감의 대리값일 뿐이다. 넷째, 전체 비용: 모델 호출 수, 입력·출력 token, 생성·검토·저장·검색 후속 호출, 총 소요 시간과 실패 복구 비용을 따로 기록한다. 현재는 token·청구 비용이 노출되지 않으므로 비용 우월성은 미측정으로 남겨야 한다.

원문 로그와 정제 교훈을 비교할 때는 단순 비교만으로 정제의 추가 효과를 주장할 수 없다. 원문에서 같은 의미를 유지한 채 교훈을 요약한 조건, 원문과 동일 정보량의 통제 텍스트, 역할 지침만 추가한 조건을 두어야 한다. 역할화의 효과는 동일 경험을 중립 역할에 제공한 조건과 특정 역할로 정제한 조건을 비교해 분리한다. 다중협의의 효과는 단일 검토자와 동일 예산의 다중 검토자를 비교해야 하며, 추가 호출 비용도 포함한다. 기억의 효과는 학습 전후 동일 모델이 아니라, 깨끗한 새 세션에서 상태를 실제로 조회하고 적용하는지로 평가해야 한다. 철회·오염 대조는 고정된 stale snapshot을 현재 적용 효과로 섞지 않도록 별도 상태 분기와 영수증을 사용해야 한다.

실행 가능한 최소 시험은 작은 규모의 현실적 과제군을 사전 등록하는 것이다. 예를 들어 후속 이슈 누락, 이전 결정을 재설명하는 과제, 중복 작업 방지 과제를 각각 학습군과 전이군으로 만들고, 세 조건(no-memory/log/lesson)을 동일한 모델·예산·출력 검증기로 반복한다. 각 조건의 반복 횟수와 중단 기준은 후보값으로 사전 명시하되 과학적으로 입증된 threshold처럼 제시하지 않는다. 성공은 정확도 하나가 아니라 행동 완료, 재설명, 회복, 인간 부담, 전체 비용의 벡터로 보고한다. 개선 없음이나 회귀도 사전에 허용된 결과로 기록한다.

아직 불가능한 것은 장기 지속 학습, 일반 업무 전반의 생산성 향상, 토큰 절감, 실제 외부 API·장비 작업의 안정성, 모델 다양성에 대한 일반화다. 현재 자료에는 현실적 업무 표본, 충분한 반복, 독립된 평가자, 실제 사용량 계측, 인간 시간 계측이 부족하다. 따라서 지금은 “조회·검증·철회 가능한 경험 저장 경로가 구현되었고, 후속 효과 실험의 설계 공백이 명확하다”까지만 결론 내리는 것이 타당하다.

반증되면 정제 교훈이 원문보다 일관되게 낫지 않다는 사실을 받아들여 정제 단계를 버리거나 역할별 요약 범위를 축소해야 한다. 교훈 제외·철회 조건에서도 같은 행동이 나오면 해당 교훈의 인과적 기여 주장을 철회한다. 형식 준수만 개선되고 실제 행동이 개선되지 않으면 출력 템플릿은 유지하더라도 생산성 효과 주장은 버린다. 비용이 늘면서 성과가 유지되면 다중협의나 후속 검토를 기본 경로로 채택하지 않는다. 인간이 결정할 것은 어떤 오류 비용을 감수할지, 경험을 공유할 권한과 철회 기준, 실제 업무에서 허용 가능한 시간·비용, 그리고 특정 교훈을 제품 규칙으로 승격할지 여부다. 데이터가 정할 수 있는 것은 어느 조건이 어떤 과제에서 어떤 결과를 냈는지까지다.
