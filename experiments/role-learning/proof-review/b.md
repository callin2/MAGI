현재 자료가 가장 먼저 입증해야 하는 주장은 “경험을 저장·검색·적용하는 역할 학습 경로가, 같은 정보와 같은 예산에서 고정 지침이나 원문 로그보다 실제 협업 결과를 개선한다”이다. 단순히 새 에이전트가 교훈을 조회했는지, 검토자가 합의했는지, JSON 정답률이 올랐는지는 이 주장을 입증하지 못한다. 특히 현재 사례는 지속·조회 경로와 계약 시험이 동작했다는 증거이지, 경험 학습의 효과나 세션 간 독립적 일반화를 보여 주는 증거가 아니다.

최소한 다음 경쟁 설명을 함께 둬야 한다. 첫째, 개선이 역할 경험 때문이 아니라 원문 로그에 포함된 정보량과 구체성 때문일 수 있다. 둘째, 고정된 출력 지침, 반복 노출, 조정자의 검토, 모델의 기초 추론만으로도 같은 결과가 나올 수 있다. 셋째, 저장·검색 경로가 판단을 개선한 것이 아니라 단순히 출력 형식을 맞추는 효과만 만들 수 있다. 넷째, 회귀나 비용 증가를 포함하면 정확도 상승이 있어도 실용적 우월성이 없을 수 있다. 따라서 no-memory, 고정 지침, 원문 로그, 정제 교훈, 교훈 제외·오염·철회 조건을 사전에 고정하고 동일한 입력 정보량과 출력 계약으로 비교해야 한다.

최소 성공 기준은 정답 필드의 엄격한 기계 판정만으로 부족하다. 각 조건에서 (1) 판단 정확도, (2) 실제 후속 행동 완료 여부, (3) 재설명·교정·중복 작업의 횟수와 시간, (4) 실패 후 회복 여부, (5) 잘못된 교훈의 적용을 거부하는 안전성, (6) 생성·검토·저장·검색·재시도까지 포함한 전체 비용을 각각 기록해야 한다. 성공은 후보 임계치를 사전에 정한 뒤, 독립 전이과제에서 일정한 방향의 개선이 반복되고 비용·인간 부담의 증가가 허용 범위에 있을 때만 주장할 수 있다. 그 수치들은 과학적으로 확정된 값이 아니라 파일럿에서 정할 후보 기준으로 표시해야 한다.

대조군은 단순히 기억 없음과 정제 교훈을 비교해서는 안 된다. 원문 로그군은 정보의 원형을 제공하고, 정제 교훈군은 같은 핵심 정보와 동일한 출력 지침을 제공해야 한다. 고정 지침군은 교훈 내용을 지침으로 재주입하여 “경험 저장” 자체의 효과를 분리한다. 교훈 제외군은 같은 상태 분기에서 해당 교훈만 제거하고, 오염군은 잘못된 교훈을 넣어 거부·회복 능력을 시험한다. 철회군은 철회 이전에 노출된 stale snapshot과 이후 새로 조회한 상태를 분리해야 한다. 과거 노출을 모델이 잊었다고 가정해서는 안 되며, 적용 영수증이 현재 상태와 일치하는지도 별도 판정해야 한다.

별도 전이과제는 동일한 Delta 사례의 ID만 바꾸는 수준을 넘어서야 한다. 재설명 누락, 후속 이슈 등록 누락, 중복 조사, 실패 원인 교정처럼 실제 목적에 가까운 과제를 준비하되, 학습 사례와 전이 사례의 정답을 직접 누출하지 않아야 한다. 신규 시스템·버전·역할·작업 유형을 일부 포함하되, 교훈의 적용 범위를 벗어난 과제도 명시해야 한다. 실제 외부 API나 장비를 사용하지 않는다면 결과는 판단과 adapter 적용 행동까지로 제한하고 업무 완료로 표현하지 않아야 한다.

원인 검증은 “교훈을 사용했다”는 문자열이나 조회 기록으로 끝나지 않는다. 교훈을 제거했을 때 특정 행동이 사라지는지, 반대로 교훈 없이도 기초 추론으로 가능한 행동인지, 잘못된 교훈을 넣었을 때 안전하게 보류하는지 확인해야 한다. 동일 입력에 대한 사전 고정된 기계 판독 스키마와 검증기를 사용하고, 누락·중첩·잘못된 형식은 조건과 관계없이 실패로 처리해야 한다. 현재 5/8 대 8/8의 차이는 출력 지침 모호성의 영향을 받았으므로 정제 교훈의 효과로 해석할 수 없다.

현재 실행 가능한 최소 시험은 작은 상태 저장소를 유지한 채, 실제 모델 호출을 포함하는 사전등록 파일럿이다. 조건별로 독립 프로세스와 독립 상태 분기를 만들고, 사례·정답 키·판정기·반복 횟수·예산·중단 조건을 먼저 고정한다. 각 호출의 입력·출력 토큰, 호출 수, 경과 시간, 검토와 저장에 든 후속 호출을 실제 사용량으로 수집한다. 사용량이 관측되지 않으면 unknown으로 남겨야 하며 문자 수를 토큰이나 비용으로 둔갑시키면 안 된다. 최소 2회 반복은 계약 시험에는 유용하지만 효과 결론에는 부족하므로, 확대 시 반복 수와 모델 다양성을 사전에 정해야 한다.

아직 불가능한 결론도 분명하다. 현재 자료만으로 정제 교훈의 독립적 우월성, 토큰 절감, 인간 시간 절감, 장기 세션 간 학습, 실제 협업 성과, 모델 일반화, 전체 비용 우월성을 주장할 수 없다. 실제 작업행동은 JSON 판단과 adapter 적용 기록까지 확인됐지만 외부 업무 완료는 검증되지 않았다. 또한 의미 충돌 자동 발견, 임의 코드·모델의 무단 파일 접근 차단, 실제 사용량 계측은 공백으로 남아 있다.

반증되면 “경험 학습이 일반적으로 유효하다”는 넓은 주장을 버리고, 확인된 범위인 상태 지속·조건부 조회·철회·충돌 보류 계약으로 축소한다. 정제 교훈이 원문보다 지속적으로 열등하면 정제 방식이나 출력 계약을 수정하고, 고정 지침과 차이가 없으면 기억 계층의 추가 가치를 주장하지 않는다. 비용과 인간 부담이 증가하면 정확도 개선만으로 도입을 정당화하지 않는다. 교훈 오염을 안전하게 거부하지 못하면 자동 적용 범위를 제한하거나 승인 단계를 둬야 한다. 인간이 결정해야 하는 것은 가치·위험 허용도·실제 도입 여부·교훈의 승인 및 철회 정책이다. 모델은 경쟁 가설, 실험 설계, 기술 판단, 결과 해석을 수행할 수 있지만 성공 기준의 가치 판단과 배포 승인을 대신할 수 없다.
