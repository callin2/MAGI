## MAGI #13~#15 독립 설계 평가 B

세 이슈는 각각 독립 계약으로 나누되, 실제 전이 시에는 하나의 판정 순서를 가져야 한다. 먼저 “누가 어떤 역할로 어떤 지속 상태를 사용했는가”를 #13에서 확정하고, 그 상태에서 나온 경험을 #14의 후보·검증 수명주기로 판정한 뒤, #15가 읽기·쓰기와 공유 범위를 적용한다. 파일이 존재하거나 역할명이 같다는 사실은 어느 단계의 성공 증거도 아니다.

### #13 역할·지속 상태 계약

최소 개념은 `Role`, `Agent`, `Task`, `Session`, `State` 다.

- `Role`: 역할 식별자, 역할 버전, 목적·책임·판단 기준, 유효 범위.
- `Agent`: 에이전트 인스턴스 식별자와 실행 주체. 같은 역할을 맡을 수 있지만 역할과 동일하지 않다.
- `Task`: 작업 식별자, 목표, 프로젝트·권한 범위.
- `Session`: 한 대화 또는 프로세스 실행 식별자와 시작·종료 시점.
- `State`: 지속 학습 상태 식별자, 상태 버전, 부모 상태, 현재 활성 여부, 귀속 범위.

작업 실행 기록에는 최소한 `role_id@version`, `agent_id`, `task_id`, `session_id`, `state_id@revision`을 남긴다. 새 세션이 시작되면 역할명으로 상태를 추론하지 않고, 명시적으로 연결된 `state_id`와 읽은 revision을 기록해야 한다. 상태가 없거나, 비활성·철회 상태이거나, 역할·프로젝트 범위가 맞지 않으면 승계는 실패하고 해당 실행은 기억 없음 조건으로 남긴다.

동일 역할의 새 에이전트는 상태의 `successor` 정책과 범위가 허용할 때만 교훈을 읽는다. 동일 역할이라도 다른 프로젝트의 전용 상태는 자동 승계하지 않는다. 역할 변경은 새 역할 버전을 만들고, 이전 상태는 유지하되 새 역할에 자동 상속하지 않는다. 겸임은 실행 단위별 주 역할과 보조 역할을 따로 기록하며, 각 역할의 전용 교훈은 해당 읽기 권한으로만 접근한다. 역할 해제는 향후 실행의 연결을 막고 기존 기록과 철회 이력은 보존한다.

대안 A는 역할당 하나의 지속 상태를 두는 단순 모델이다. 구현과 재시작 연결이 쉽지만, 동일 역할의 프로젝트별 맥락이 섞이는 위험이 크다. 대안 B는 `role × project` 또는 `role × scope` 상태를 기본 단위로 하고, 명시적 공유만 별도 상태로 승격한다. 격리는 강하지만 상태 수와 연결 관리가 증가한다. 최소 실험에는 B를 채택한다. 이유는 #15의 전용·공유 시험과 오염 반례를 한 번의 식별 체계로 검증할 수 있기 때문이다.

가장 강한 반례는 같은 `reviewer` 역할명을 새 세션에 부여했지만, 실제로는 다른 state revision을 읽었거나 이전 상태가 철회된 경우다. 이름과 파일이 같아도 연결 영수증이 없으면 승계 성공으로 판정하지 않는다.

최소 실행 경로는 상태 manifest와 세션 시작 기록을 구현하는 것이다. 시작 시 manifest의 역할·범위·활성 revision을 검증하고, 실행 종료 시 실제 읽은 revision과 적용된 교훈 ID를 기록한다. 후속 이슈는 역할 버전 변경, 겸임, 상태 철회·복구, 중복 연결 방지다.

### #14 교훈 후보·수명주기 계약

경험 원문과 교훈은 분리한다. 경험 레코드는 사건, 관측 사실, 실행 결과, 사용자 교정 또는 검증 로그를 보존한다. 교훈 후보는 `candidate_id`, 출처 경험 ID, 원인 가설, 제안 규칙, 적용 조건, 금지 조건, 근거 유형, 검증 상태, 생성 revision을 갖는다. 검증 상태는 `candidate`, `validated`, `provisional`, `deferred`, `rejected`, `retired`로 제한한다.

후보 생성은 명시적 기억 요청 없이도 가능하지만, 생성과 확정을 분리한다. 합의된 목표 안의 기술 판단은 에이전트가 재현 시험·정적 검토·독립 사례 비교를 통해 `validated` 또는 `provisional`로 올릴 수 있다. 새 취향, 제품 정책, 권한 확대, 공유 범위 선택은 인간 또는 기존 승인 정책이 결정해야 한다. 모든 후보에 인간 승인을 요구하면 학습 경로가 중단되므로, 인간 승인은 가치·권한 변경에만 요구한다.

반영 판정은 적용 조건 일치, 근거 상태, 현재 revision, 충돌 여부를 확인한다. 단일 성공·칭찬·불만은 후보 생성 근거일 수 있으나 일반 규칙 확정 근거가 아니다. 새 반례가 나오면 후보를 즉시 삭제하지 않고 `rejected` 또는 `retired`로 전환하며, 이후 검색 결과에서 제외한다. 수정은 새 revision으로 남기고 기존 revision과 차이를 연결한다. 철회는 새 실행에 전달되어야 하며, 이미 생성된 실행 기록을 소급 변경하지 않는다.

대안 A는 후보를 수동 검토 후에만 적용하는 보수 모델이다. 오염은 낮지만 명시적 기억 요청 없는 학습이라는 목적을 약화한다. 대안 B는 기술적·반복 가능한 항목을 자동 `provisional`로 적용하고, 성과 반증이나 가치 변경이 있을 때만 인간 판단을 요구한다. 최소 검증에는 B를 채택한다. 단, provisional 교훈은 적용 사실과 위험 수준을 실행 기록에 표시한다.

강한 반례는 사용자가 한 번 칭찬한 행동을 “항상 선호되는 규칙”으로 만든 경우다. 성공 결과와 원인 가설을 분리하고, 다른 조건의 반례 시험을 통과하기 전에는 provisional 이상으로 승격하지 않는다. 또 하나의 반례는 낡은 교훈을 수정했지만 검색 캐시가 이전 revision을 계속 제공하는 경우다. 검색 결과에는 활성 revision과 철회 목록을 함께 대조해야 한다.

최소 실행 경로는 후보 JSON 계약, 상태 전이 함수, 적용 전 조건 검사, 철회 목록 필터다. 후속 이슈는 근거 강도 계산, 충돌 판정, 캐시 무효화, 후보 품질 평가다.

### #15 귀속·공유 계약

각 지식 항목에 `owner_scope`, `read_scope`, `write_scope`, `share_grant`, `source_state`, `revision`, `revoked_at`을 둔다. 기본값은 전용이다. 전용은 특정 에이전트 또는 역할·프로젝트 조합만 읽고 쓸 수 있다. 동일 역할 승계는 명시된 successor 범위가 있을 때 허용한다. 다른 역할 공유는 별도의 `share_grant`가 있고, 공유 대상·목적·유효 기간·허용 revision이 기록된 경우에만 허용한다. 공유는 복사가 아니라 원본 revision에 대한 읽기 권한으로 시작해, 필요하면 대상 역할용 파생 지식으로 생성한다.

쓰기 권한과 읽기 권한은 분리한다. 공유받은 역할은 원본을 수정하지 못하고, 새 후보를 자신의 범위에 생성한다. 공유 범위 축소나 역할 해제 시 새 읽기를 즉시 차단하며, 철회 revision은 검색·적용 단계에서 필터링한다. 충돌 우선순위는 안전·권한 제한, 최신 명시적 철회, 좁은 범위, 더 구체적인 적용 조건, 최신 검증 revision 순이다. 충돌을 자동 병합할 수 없으면 둘 다 보류하고 실행을 중지하거나 기억 없음 경로로 전환한다.

대안 A는 전면 비공유다. 격리는 명확하지만 동일 역할의 전이와 #16의 공유 시험을 수행할 수 없다. 대안 B는 전용 기본 + 명시적 grant 공유다. 관리 필드가 더 필요하지만 RL-04의 범위와 오염 반례를 직접 검증할 수 있으므로 채택한다.

강한 반례는 역할 R의 전용 교훈이 역할 S의 검색 결과에 노출되거나, R에서 철회한 공유 교훈이 S의 캐시에 남아 적용되는 경우다. 수용 조건은 S가 해당 항목을 조회·입력에 포함할 수 없어야 하며, 철회 후 새 실행에서 적용 ID가 0이어야 한다. 역할·프로젝트 맥락이 바뀐 뒤에도 이전 교훈이 자동 적용되면 실패다.

최소 실행 경로는 scope 검사, grant 목록, 활성 revision·철회 필터를 검색 어댑터에 추가하는 것이다. 후속 이슈는 공유 승인 UI 또는 API, grant 변경 이력, 캐시 무효화와 감사 조회다.

### #16 시험 성공·실패 기준

실험 전에 경험 작업과 별도 전이 작업, 역할 R/S, 새 세션·새 프로세스, 동일 예산을 고정한다. 세 조건을 비교한다.

1. 기억 없음.
2. 원문 로그 검색.
3. 정제 교훈 검색.

성공은 전이 작업 입력에 원문 복사나 별도 재설명 없이 활성 `state_id@revision`, 교훈 ID, 적용 조건, 실제 판단·행동 결과가 연결되고, 역할 격리·지정 공유·맥락 변경·철회가 기대대로 작동하는 경우다. 최소 두 번 이상의 별도 전이 실행에서 같은 역할 교훈이 재사용되고, 공유되지 않은 전용 교훈은 S에 나타나지 않아야 한다. 오류·재설명·중복 작업·잘못된 확신과 생성·검토·검색·조정 비용을 모두 기록한다.

파일 저장, 검색 성공, 적용 기록만으로는 성공이 아니다. 실제 판단 개선이 없거나 비용 증가가 이득보다 크면 효과 없음으로 기록한다. 철회 후 재사용, 역할 오염, 상태 연결 누락, revision 불일치, 원문 복사 의존은 즉시 실패다. 일반화 범위와 반복 횟수도 결과에 명시하며, 이슈 완료는 실행 증거와 비용 측정이 남은 뒤에만 허용한다.
