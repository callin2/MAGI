# 독립 설계 검토 입력 — #10, #13, #14, #15

목표: 기존 학습 사례를 재사용하여 역할별 경험이 다음 작업에서도 유지·사용되는 최소 계약을 만들고 실제 전이 시험으로 이어간다. 아래 사례는 문서/일부 소스 확인이며 직접 운영 효과 증거는 없다.

각 평가자는 서로 의견을 모르고 가설 경쟁형으로 평가한다. 역할 목록이나 가설을 강제로 배정하지 않는다. 최소 2개 대안, 각 계약의 구체 결정(식별·버전·승계 / 후보·채택·보류·철회 / 범위·공유·충돌), 가장 강한 반례, 최소 실행 경로, 후속 이슈 범위, #16 시험 성공·실패 기준을 제안하라. 설계가 미리 확정됐다고 가정하지 말라. 모든 교훈에 인간 승인을 요구하지 말고 기존 목표 안의 기술 판단과 새 가치 선택을 구별하라. 추상성과 작은 완결성을 우선한다.

다른 평가·파일·웹은 읽지 말고 이 입력만 사용한다. 원문 최종 응답만 반환하고 파일/이슈/중앙보고는 작성하지 않는다. 조정자가 전원 완료 뒤 기록한다.

## 조합 방향과 공백

가져올 기초는 기존 git/파일 기반 지속·버전 관리, JSON 자료 계약, 새 대화에 관련 교훈을 제공하는 기존 에이전트 실행 능력이다. 전체 Hermes/Letta/OpenClaw 런타임을 다시 구현하지 않는다. 제품 설치·이관은 이 작은 검증의 선행 조건으로 강제하지 않는다.

MAGI의 추가 부분은 (1) 경험과 교훈 후보의 근거 연결, (2) 승인된 목적 아래 기술 검증으로 확정 가능한 항목과 새로운 가치 선택 구분, (3) 역할/프로젝트별 범위와 충돌·철회, (4) 실제 전이·총비용 반증이다. 특정 엔진을 최종 선정했다는 뜻은 아니다. 독립 설계 검토 후 최소 실험 adapter를 정한다.

| 경로 | 재사용 가능한 기초 | MAGI가 명시할 공백 |
|---|---|---|
| 경험 → 후보 | 에이전트 reflection/skill 생성 패턴 | 원인 가설과 관측 사실 분리, 감정만으로 확정 금지 |
| 후보 → 검증 → 반영 | 기존 시험·git diff·버전 관리 | 기술/가치 판단 경계, 승격/보류/기각 조건 |
| 반영 → 다음 세션 | 지속 파일 + 새 실행의 관련 파일 조회 | 역할·지속 상태 ID, 실제 읽은 revision, 즉시 철회 처리 |
| 재사용 → 효과 | 기존 모델 실행·평가 도구 | 별도 과제, no-memory/log/lesson 대조, 생성·검색까지 총비용 |

## 우리 협업 레시피

원천은 사용자가 이 대화에서 반복해 명시한 교정과 현재 확인 가능한 이슈 작업이다. 과거 수 주의 전체 로그를 분석했다고 주장하지 않는다.

| 문제 / 기대 행동 | 적용 조건 | 예외·수정/기각 조건 | 관측 지표 |
|---|---|---|---|
| 평가 결론 뒤 후속 이슈를 빠뜨림 → 합의된 후속 작업을 중복 확인 후 선등록 | 실행할 후속 작업이 도출된 경우 | 사용자가 중단·논의만 요청한 경우 진행하지 않음. 새 목표를 추측해 만들지 않음 | 빠진 과제·재지시 횟수 |
| 동일 설명·교정 반복 → 관련 결정·교훈을 조회해 행동에 적용 | 같은 목적·범위와 유효 조건 일치 | 범위/권한/목표가 바뀌면 기존 규칙을 보류·재검토 | 재설명·동일 오류 |
| 완료 작업 재수행 → issue/산출물 최신 근거 먼저 확인 | 다른 실행·에이전트의 결과를 이어받을 때 | 오래된 상태는 확인 후 사용, 완료 표지만 맹신하지 않음 | 중복 호출·중복 산출 |
| 같은 실패 반복 → 실패 조건과 반증을 교훈 후보로 남김 | 원인·재현 조건을 식별할 수 있을 때 | 일회성 잡음/원인 불명이면 보류 | 반복 실패·회복 비용 |
| 불필요한 인간 질의 → 합의한 목표 안에서 기술 판단 진행 | 근거·제약·검증 방법이 있는 경우 | 새로운 취향·가치·권한 선택은 인간 판단 필요 | 불필요 질의·무단 가치 결정 |
| 파일 저장/합의를 완료로 과장 → 저장·조회·적용·성과를 분리 | 모든 학습 보고 | 효과가 없으면 그대로 기록하고 적용을 철회·수정 | 근거 없는 완료 주장 |

효과 검증은 #16에서 수행한다. 반복 횟수·오류율·재설명·시간·모델 호출·측정 가능한 토큰을 기록한다. 총비용 미측정이면 토큰 효율 개선을 주장하지 않는다. #13~#15의 계약 정의 뒤, 필요한 최소 구현을 별도 이슈에 먼저 등록한다.

## 목적 — 사용자가 추가 요청한 요구사항

에이전트마다 역할을 부여할 수 있어야 하며, 해당 역할을 수행하면서 배운 내용을 다음 작업에서도 유지하고 활용할 수 있어야 한다. 작업이나 대화가 바뀔 때 같은 설명·교정·시행착오를 반복하는 비용을 줄이는 것이 목적이다.

역할은 특정 직무 목록으로 고정하지 않는다. 사업·기술 판단부터 설계 등 여러 맥락에서 정의할 수 있는 추상적인 책임과 판단 기준으로 취급한다.

## 기능 요구사항

### RL-01. 에이전트별 역할 부여

- 에이전트에 역할과 그 목적·책임·판단 기준을 부여할 수 있어야 한다.
- 역할, 개별 에이전트의 정체성, 작업, 대화 세션을 구분할 수 있어야 한다.
- 역할과 에이전트 수의 대응 관계 또는 역할별 사용할 모델을 이 요구사항에서 고정하지 않는다.

### RL-02. 경험에서 배운 내용의 지속

- 역할 수행 중 얻은 유효한 교훈·절차·판단 기준 보완을 지속적으로 보존할 수 있어야 한다.
- 성공·실패·사용자 교정 등의 경험에서 학습 후보를 추출할 수 있어야 하며, 매번 별도의 '기억해' 요청을 전제로 하지 않는 동작을 지원해야 한다.
- 작업 이력의 단순 저장과, 경험에서 도출한 재사용 지식·스킬을 구분한다. 칭찬·불만만으로 원인을 확정하거나 잘못된 규칙을 정당화하지 않는다.

### RL-03. 다음 작업·세션에서 재사용

- 같은 역할을 수행하는 에이전트가 다음 작업에서 관련 학습 내용을 찾아 실제 판단·행동에 활용할 수 있어야 한다.
- 대화 세션이나 실행 프로세스가 끝났다는 이유만으로 학습 내용이 사라지지 않아야 한다. 지속 상태를 다시 연결하는 방법을 제공해야 한다.
- 같은 역할 이름을 새 에이전트에 부여하는 것만으로 학습이 승계됐다고 처리하지 않는다. 어느 지속 상태를 사용했는지 식별할 수 있어야 한다.

### RL-04. 전용 경험과 공유 경험의 범위

- 에이전트 또는 역할 전용으로 유지할 경험과 여러 에이전트가 공유할 지식을 구분할 수 있어야 한다.
- 공유 범위를 명확히 지정해 다른 역할의 규칙·맥락이 의도 없이 섞이는 것을 방지해야 한다.
- 특정 에이전트의 교훈이 동일 역할의 다른 실행에 승계되는 조건과, 다른 역할로 공유되는 조건을 명시할 수 있어야 한다. 자동 공유 여부나 저장 구조는 아직 확정하지 않는다.

### RL-05. 학습 반영과 효과의 추적

- 어떤 경험에서 무엇을 배웠고, 어느 범위에 반영했으며, 다음 작업에서 무엇을 불러와 적용했는지 추적 가능해야 한다.
- 저장 성공, 검색/로드 성공, 실제 적용, 작업 성과 개선을 각각 구분해야 한다.
- 잘못되거나 낡은 교훈을 수정·제외할 수 있어야 하며, 반영·수정 기준은 검증 설계에서 구체화한다.

## 수용 기준 — 구현 후 확인할 사항

- [ ] 서로 다른 역할을 가진 에이전트를 정의하고 각 역할의 목적·책임·판단 기준을 확인한다.
- [ ] 역할 수행 중 실제 경험에서 재사용 교훈을 추출·저장하는 경로를 확인한다. 명시적 기억 요청 없이 반영하는 조건도 시험한다.
- [ ] 첫 작업에서 배운 내용을 별도 다음 작업에서 다시 설명하거나 복사해 주지 않고 검색·적용하는 증거를 남긴다.
- [ ] 새 대화 또는 실행 재시작 뒤 지속 상태를 다시 연결해 같은 교훈을 사용할 수 있는지 확인한다.
- [ ] 전용 지식이 다른 역할에 의도 없이 적용되지 않고, 지정한 공유 지식은 필요한 역할에만 전달되는지 확인한다.
- [ ] 잘못된 교훈의 수정·제외가 이후 작업에 반영되는지 확인한다.
- [ ] 학습 전후의 같은 실수·중복 작업·재설명 감소와 시간·토큰·호출 비용을 비교한다. 비교 조건과 미측정 항목을 표시한다.
- [ ] 단순 파일 저장이나 에이전트 간 합의를 학습 효과 입증으로 처리하지 않는다.

## 재사용 검토 대상

직접 새로 구현하기 전에 #10의 기존 사례를 검토한다.

- Hermes: 목적별 profile과 그 profile의 memory·skills 보존.
- Letta: 영속 agent identity와 여러 대화 사이의 memory 유지, 선택적 공유 block.
- OpenClaw: agent별 workspace와 learned skill 귀속, 별도의 공용 배포 범위.

이는 공식 문서 기반 참고 사례다. 특정 제품을 채택했다거나 MAGI에서 동작을 검증했다는 뜻은 아니다.

## 설계에서 결정할 항목

역할과 에이전트 정체성의 관계, 학습 내용의 귀속·승계·공유 정책, 관련 지식 검색 방법, 반영·검증·수정 조건, 역할 변경 시 이전 교훈의 처리 방식, 성과 평가 방법. 모델 가중치 변경을 필수 조건으로 하지 않으며 구현 제품·저장소·API를 이 단계에서 확정하지 않는다.

## 현재 상태

요구사항 등록 단계다. MAGI에서 역할별 영속 학습을 구현하거나 다음 작업·새 세션에서 검증한 상태는 아니다. 후속 설계·구현·실험은 기존 covering issue를 확인하거나 별도 이슈에 먼저 등록한 뒤 수행한다.
