# MAGI 해석·판단 기준 품질 평가 계약 v0.1

## 1. 상태와 목적

이 문서는 새로운 유형의 대상을 다루는 MAGI 판단 구조의 연구용 평가 계약이다. **v0.1은 구현 요구사항이나 성능 보증이 아니며, 연구에서 무엇을 기록하고 어떻게 구분해 평가할지 정하는 초안**이다. 현재 확인된 것은 개념 요구와 제한된 확률 모형의 관찰뿐이다. 실제 AI 협의, 해석 생성, 판단 기준 생성의 효과는 아직 검증되지 않았다.

평가 단위는 하나의 대상에 대한 한 번의 판단 기록이다. 평가자는 결과의 정답 여부만 보지 않고, 대상의 해석과 그 해석에 사용한 기준이 어떤 근거와 한계를 갖는지 평가한다.

## 2. 최소 기록 스키마

각 기록은 다음 항목을 포함한다. 값이 없으면 빈칸으로 두지 말고 `미제시` 또는 `판정불가`를 명시한다.

| 항목 | 기록할 내용 |
|---|---|
| 식별·시점 | 사례 ID, 입력 시점, 판단 버전 |
| 해석 | 대상이 무엇인지, 어떤 문제로 이해했는지, 대안 해석 |
| 기준 | 무엇을 좋은 판단으로 볼지, 기준의 적용 범위와 이유 |
| 사실 | 관측·출처로 확인된 내용과 확인 시점 |
| 가치 | 우선순위나 바람직함에 관한 선호·원칙 |
| 제약 | 외부에서 주어진 조건, 권한, 자원, 시간 |
| 근거 | 각 주장·기준·선택을 지지하는 자료와 연결 관계 |
| 불확실성 | 모르는 내용, 가정, 추정, 해소되지 않은 이견 |
| 반증 | 해석·기준·선택이 틀렸다고 볼 관찰 또는 조건 |
| 선택 | 현재 채택한 판단, 유보 또는 추가 탐색 결정 |
| 재검토 | 다시 판단할 사건·조건·시점과 필요한 관측 |

사실·가치·제약은 서로 바꾸어 기록하지 않는다. 사실에 관한 근거가 강하다는 이유만으로 가치의 우선순위가 정당화되었다고 기록하지 않는다.

## 3. 해석의 타당성 평가

타당한 해석은 낯선 대상을 임의의 이름으로 바꾸는 것이 아니라, 관찰된 특징·목적·제약을 설명하고 다른 해석과 구별되는 결과를 제시해야 한다. 해석은 다음을 밝혀야 한다.

- 어떤 관찰 또는 질문에 근거하는가.
- 무엇을 설명하고 무엇을 설명하지 못하는가.
- 경쟁 해석과 어떤 관측·실험으로 구별되는가.
- 해석이 바뀌어야 하는 조건은 무엇인가.

표현만 바꾼 말바꿈은 타당한 해석으로 세지 않는다. 원래 주장과 결론이 같고, 새 예측·구별 기준·추가 질문·반증 조건을 만들지 못하면 `말바꿈`으로 기록한다. 여러 표현이 같은 내용을 가리킬 수 있다는 판단 자체도 근거와 구별 기준을 남긴다.

## 4. 루브릭

각 항목은 0~2점으로 평가한다. `해당없음`은 해당 능력이 사례의 요구에 실제로 포함되지 않을 때만 사용하고 점수 계산에서 제외한다. 필요한 정보가 없거나 근거가 충돌해 평가할 수 없으면 `판정불가`로 표시하며 0점으로 임의 환산하지 않는다.

| 평가 항목 | 0 | 1 | 2 |
|---|---|---|---|
| 해석 명료성 | 대상·문제가 불명확 | 일부 명료하나 범위가 모호 | 대상, 문제, 범위가 구분됨 |
| 해석의 근거성 | 근거 없음 또는 말바꿈 | 일부 근거 있으나 연결이 약함 | 관찰과 해석의 연결이 추적됨 |
| 해석 다양성 | 대안 없음 또는 허위 다양성 | 제한된 대안 제시 | 실질적으로 구별되는 대안 제시 |
| 기준 명료성 | 기준 없음 | 기준은 있으나 이유·범위가 불명확 | 기준, 이유, 적용 범위가 명시됨 |
| 기준 적합성 | 대상과 맞지 않음 | 일부 상황에서만 적합 | 대상·목적·제약과의 적합성이 설명됨 |
| 사실·가치·제약 구분 | 뒤섞임 | 일부 구분 | 서로 다른 성격과 관계가 명확함 |
| 불확실성·이견 | 숨기거나 과장 | 일부 표시 | 가정·미지·이견·한계가 구분됨 |
| 반증 가능성 | 실패 조건 없음 | 추상적 실패 조건 | 관찰 가능한 반증 조건이 있음 |
| 선택·유보의 비례성 | 근거 없이 결정/유보 | 이유가 부분적 | 위험·근거·비용에 비례한 이유가 있음 |
| 재검토 가능성 | 재검토 조건 없음 | 조건이 모호함 | 사건·시점·필요 관측이 명시됨 |

총점은 참고용이다. 낮은 한 항목을 평균 점수로 상쇄하지 않으며, `판정불가`가 핵심 항목에 있으면 전체 결론도 `평가 유보`로 표시할 수 있다.

## 5. 실제 출력과 사후 평가의 분리

실제 출력에는 시스템이 당시 이용할 수 있었던 입력, 해석, 기준, 선택, 불확실성, 유보·재검토 조건만 포함한다. 사후 평가에는 나중에 확인된 사실, 기준의 적합성 판단, 반증 발생 여부, 결과와 변경 이유를 별도로 기록한다. 사후에 알게 된 정답이나 결과를 당시 출력에 소급해 넣지 않는다. 따라서 “당시 합리적이었는가”와 “결과적으로 맞았는가”를 별도 필드로 보고한다.

## 6. 대표 실패 분류

`잘못된 합의`는 여러 주체가 같은 근거 또는 같은 오해를 공유해 일치했지만, 중요한 반례·대안 해석·미지의 내용을 누락한 경우다. 합의 수나 확신 표현만으로 타당성을 입증하지 않는다.

`과도한 유보`는 추가 관측이 판단을 실질적으로 개선할 가능성이 낮거나, 이미 충분한 근거와 낮은 위험이 있는데도 필요한 선택을 계속 미루는 경우다. 유보는 무조건 높은 품질이 아니며, 유보 이유·기대 정보·자원 비용을 기록해야 한다.

## 7. 평가자 불일치 처리

평가자는 먼저 독립적으로 기록하고 점수와 근거를 제출한다. 항목별 점수가 다르면 각 평가자는 해당 스키마 항목과 출력 문장을 인용해 이유를 설명한다. 불일치가 해석의 의미에 관한 것인지, 루브릭 적용에 관한 것인지 구분한다. 합의가 되지 않으면 평균이나 다수결로 숨기지 않고 점수 범위, 쟁점, 판정불가 사유를 보존한다. 루브릭 문구 자체가 반복적으로 갈리면 사례를 억지로 판정하지 말고 v0.1의 수정 후보로 등록한다.

## 8. 결론 표기

각 사례의 결론은 `유지`, `수정`, `기각`, `유보` 중 하나를 사용한다. 결론에는 핵심 근거, 미해결 불확실성, 반증 조건, 다음 재검토 조건을 함께 남긴다. 이 계약은 범용 구조의 품질을 시험하기 위한 최소 기록·판정 형식이며, 어떤 구조가 우월하다는 실험 결과를 선언하지 않는다.
