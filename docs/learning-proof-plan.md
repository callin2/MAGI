# MAGI 판단: 학습 효과 입증에 필요한 것 — #18

[문서 목차](README.md) · 초기 제안 기록. 후속 실행은 [실제 업무 파일럿](recursive-work-pilot.md)과 [효과 비교](effectiveness-verification-20261018.md)에 있다. 제안의 48회와 이후 실행의 22회, F 조건의 정의는 서로 다르다.

## 판정

**실제 실패·교정에서 얻은 경험이, 다시 설명하지 않은 새 작업에서 실제 행동을 개선하는지 먼저 확인한다.** 그다음 정제, 역할화, 다중 협의의 추가 이득을 따로 비교한다. 현재 대화 안에서 반복 지침을 따르는 것과 세션 간 경험 학습을 구분한다.

세 독립 에이전트에게 같은 입력(`b535d3d1e375800d7236bcad2fce18cba5e8bffb68a227cff95019c52617136a`)을 주고 타 의견은 공유하지 않았다. 전원 완료 후 [평가 원문](../experiments/role-learning/proof-review/)을 보존하고 이 문서를 작성했다. 같은 모델·공통 쟁점 입력의 영향이 있으므로 합의는 경험적 입증이 아니다.

## 공통 결론과 조정자의 판단

| 쟁점 | 독립 평가에서 공통으로 요구한 것 | 실행에 사용할 해석 |
|---|---|---|
| 무엇이 달라져야 하나 | 새 세션의 행동 완료, 반복 오류와 인간 부담 | ‘이슈를 만들겠다’는 응답 대신 tracker의 실제 등록·중복 여부를 검사 |
| 무엇과 비교하나 | 고정 지침·원문 로그·정제 교훈·기초 모델 | 지침만으로 충분하다는 경쟁 가설도 동등하게 검증 |
| 원인이 경험인가 | 교훈 제외·오염·철회, 깨끗한 상태 분기 | 동일 조건에서 특정 교훈만 바꾸고 행동 차이 확인 |
| 어떤 비용인가 | 학습·저장·조회·재시도·검토·인간 개입 전체 | 관측하지 못한 비용은 unknown. 문자 수를 token으로 바꾸지 않음 |
| 효과 없으면 | 정제/협의 단계를 기본값으로 채택하지 않음 | 간단한 고정 지침·검색으로 충분하면 그 경로를 선택 |

평가 A는 변화 없음의 원인이 과제의 쉬움이나 검색 실패일 가능성도 강조했다. B는 고정 지침에 같은 내용을 제공하는 대조를 가장 명시적으로 요구했다. C는 역할화와 다중협의를 독립 요인으로 분리하는 점을 강조했다. 세 보고서는 큰 방향에서 유사하며 실제로 상충하는 실증 결과를 제공하지 않았다.

아래 세 부분은 조정자가 원문을 그대로 채택하지 않고 보완한 것이다.

1. **‘no-memory와 같은 정보량’은 그대로는 성립하지 않는다.** task와 필수 지침·도구·기본 모델은 같게 두되 경험 접근이 없는 군은 보유 정보가 적다는 사실을 공개한다. 기억의 전달 효과와 표현 방식의 효과를 서로 다른 비교로 분리한다. 같은 핵심 정보를 가진 log/lesson/fixed-rule 대조가 정제의 추가 이득을 판단한다. 같은 문자 수만으로 같은 의미 정보량을 보장하지 않는다.
2. **모든 효과를 한꺼번에 입증하지 않는다.** 행동 전이, 정보 정제, 역할화, 다중 협의, 총비용을 단계별 주장으로 분리한다. 토큰 계측 부재 때문에 행동 시험까지 멈추지는 않는다. 계측 전에는 효율 주장만 보류한다.
3. **기술 교훈의 승인·철회까지 매번 인간에게 넘기지 않는다.** 기존 목적·제약과 재현 근거 아래서는 에이전트가 판단한다. 새 가치·권한·위험 허용 수준만 기존 인간 결정이 없을 때 질의한다. ‘인간이 모든 성공 기준을 새로 정해야 한다’는 필수 절차도 추가하지 않는다. 이미 지시된 이슈 선등록·무단 공유 금지 등은 그대로 판정 기준이다.

## 먼저 필요한 실제 실행 경로

현재 synthetic events는 실제 에이전트가 작업하다 실패한 관측이 아니다. 다음 실행은 다음 경로를 모두 통과해야 한다.

`실제 도구 작업 → 관측된 실패/교정 → 자동 작업 종료 검토 → 후보·검증·저장 → 이전 대화 없는 새 에이전트 → 관련 기억 조회 → 별도 작업의 도구 실행 → 결과 판정`

조정자가 답을 알고 교훈을 직접 넣는 것, 이전 대화를 새 작업 프롬프트에 복사하는 것, 새 에이전트에게 시험 정답을 알려주는 것은 이 경로를 우회한다. 학습 과정에 고정 reflection 지침이 있다면 공개한다. 그것 자체는 새로운 사용자 ‘기억해’ 요청이 아니다.

## 최소 행동 시험: 제안된 구체 실행안

새 제품이나 큰 설치를 먼저 요구하지 않는다. 기존 adapter와 로컬 임시 tracker를 이용해 실제 쓰기·조회 결과를 검사한다. 실제 GitHub 운영의 삭제·중복 생성으로 시험하지 않는다. 로컬 도구 행동의 결과는 로컬에서만 입증하며 외부 업무 완료로 표현하지 않는다.

과제군은 이번 협업에서 확인한 문제 세 가지로 한정한다.

| 과제군 | 경험 작업에서 관측할 것 | 새로운 전이 작업 | 기계 판정 |
|---|---|---|---|
| 후속 등록 누락 | 평가 결론에 실행 가능한 후속이 있는데 기록을 누락하거나 완료했다고 말함 | 다른 사업/설계 결론에서 실행 과제와 미결 가치 질문이 함께 등장 | 필요한 과제의 실제 issue·부모·완료 기준 존재, 미결 가치의 무단 확정 없음 |
| 중복 작업 | 이미 범위를 포함하는 이슈/산출물을 확인하지 않고 새로 만듦 | 이름과 표현이 바뀐 기존 과제를 이어받음 | 기존 issue 재사용, 중복 생성·불필요 재실행 수 |
| 실패 회복·완료 근거 | 실행 오류나 반례 뒤 같은 접근을 반복하거나 완료를 과장함 | 다른 모듈의 유사 원인·다른 오류 메시지 | 검증된 수정·회복 및 맞는 완료 상태, 근거 없는 완료 0건 |

필수 사용자 지침과 권한은 모든 군에 유지한다. 고정 지침을 의도적으로 빼고 잘 지키지 못했다고 학습의 승리로 만들지 않는다. 지침만으로 이미 충분한 과제라면 학습의 추가 이득 없음으로 기록한다.

첫 표본 후보는 과제군당 경험 1개와 별도 전이 2개(가까운 맥락/바뀐 맥락), 전이 6개다. 4조건×2반복이면 48개의 전이 실행이다. 이는 계측·판정기 검증을 위한 작은 파일럿 제안이며 통계적으로 충분한 표본 수라는 주장이 아니다. 실제 예산은 호출의 전체 사용량을 관측한 뒤 확정하고 실행 전에 고정한다. 제안 수를 성공 결과에 따라 바꾸지 않는다.

### 비교 조건과 각 비교가 말해 주는 것

- G: 경험 없음. task·필수 지침·도구는 동일하다. 기초 모델과 현재 지침만으로 충분한지 본다.
- F: 사람이 미리 고정한 협업 규칙. hindsight로 전이 정답을 넣지 않는다. 새 경험 뒤 갱신하지 않아 고정 지침으로 충분한지 본다.
- L: 실제 경험 원문을 지속·검색한다. G 대비는 기억 전달의 전체 효과이며 정보량 차이를 포함한다.
- E: 같은 경험에서 시스템이 추출·검증한 조건부 교훈을 지속·검색한다. L 대비는 정제의 추가 효과다.

추가로 동일 규칙을 수동 고정 입력한 진단은 **검색·선택·적용 경로**의 손실을 확인하는 상한 대조다. 그 결과만으로 경험 생성의 자동성을 입증할 수 없다. 경험 정제 내용과 전이 정답을 같은 사람/모델이 사후 재구성하지 않도록 생성·판정 경로를 분리한다.

처음에는 역할 정의와 판단 모델을 모든 군에서 같게 둔다. 역할화의 이득은 이후 동일 정보의 중립/역할별 범위 비교로, MAGI 협의의 이득은 이후 같은 총자원의 단일/다중 비교로 시험한다. 둘을 기억 효과에 합쳐 주장하지 않는다.

## 실행 전에 고정할 것

1. 원본 경험과 별도 전이 사례, 정답/허용 결과, 실제 tracker 상태를 검사하는 판정기. 새 세션은 자기 입력과 허용된 도구·state만 접근한다.
2. 모호하지 않은 JSON 스키마·실제 도구 호출 형식. 형식 오류와 내용 오류를 따로 기록하되 실행 실패를 성공으로 사후 보정하지 않는다.
3. 각 군의 상태 분기·revision·순서·반복·모델·도구 및 중단 조건. tool/setup 실패는 성능 결과와 구분해 남긴다.
4. 교훈 한 항목 제외, 적용 범위 밖 맥락, 잘못된 교훈, 수정·철회 후 깨끗한 실행. stale 결과를 현재 적용으로 수용하지 않는다.
5. 사건→후보→검증→저장→조회→도구 실행→검사 결과와 usage 기록. 개별 응답뿐 아니라 전체 경로에 ID를 연결한다.

## 성공·반증·인간 부담

우선 관측할 것은 필요한 과제 누락, 중복 생성, 반복 오류, 근거 없는 완료, 무단 가치 결정, 유효한 작업 완료다. 이는 이미 합의된 요구에 대한 판정이며 임의 선호를 새로 만드는 것이 아니다. 작은 표본은 건별 결과와 짝지은 차이를 보이고, 충분한 반복 후 불확실성 범위를 계산한다. 성공 사례만 골라 일반화하지 않는다.

교훈을 빼도 같으면 해당 과제에서 그 교훈의 필요성 주장은 지지되지 않는다. 그것만으로 교훈 자체가 거짓이라고 삭제하지는 않는다. G/F와 차이가 없으면 추가 기억의 효용을 주장하지 않는다. E가 L보다 나쁘면 정제 손실과 조회·출력 경로를 확인하고 정제 단계를 줄이거나 제외한다. MAGI가 같은 총비용의 단일 모델보다 이득이 없으면 모든 작업의 기본 경로로 두지 않는다.

스크립트가 제공하는 교정 횟수는 ‘인간 시간 절감’의 증거가 아니다. 첫 시험에서는 이를 통제된 교정 개입 수로 보고한다. 인간 부담 주장을 하려면 이후 동의된 실제 협업에서 사용자 재지시·설명·검토 시간을 관측해야 한다. 사용자에게 같은 일을 반복시키는 추가 부담을 새로 요구하지 않는다.

총비용은 모델 응답 생성뿐 아니라 reflection·검증·검색·저장·조정·재시도·원문 보존 후속 호출까지 포함한다. 현재 도구에서 token/청구가 보이지 않는 공백은 계량 경로로 해결해야 한다. 실제 값을 얻기 전에는 완료율·오류 감소에 대한 제한된 결론만 가능하다.

## 남은 작업 연결

#18을 이 검토의 covering issue로 재사용했다. 세 독립 평가 전원 완료 뒤 결과를 기록했다. 실제 경험→로컬 작업 행동 전이 시험은 별도 하위 이슈로 등록하고 #17의 adapter를 재사용한다. 비용/출력 계약의 확대 검증은 기존 #18 범위에 유지해 같은 작업의 중복 이슈를 만들지 않는다.

이번 산출물은 실행 가능한 검증 설계다. 새 행동 시험의 실행 결과나 학습 효과 입증으로 표시하지 않는다.
