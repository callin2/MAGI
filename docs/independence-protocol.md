# MAGI 독립 평가·공통 오판 프로토콜 v0.1

[문서 목차](README.md)

## 목적과 지위

이 프로토콜은 여러 판단 주체의 독립성, 공통 오판, 앵커링, 정보·자원 차이를 관찰하기 위한 연구 절차 초안이다. 범용 추상 판단 구조의 비교를 위한 것이며, 어떤 구조의 실제 성능이나 우월성을 이미 검증했다는 뜻이 아니다. 구조의 이름보다 관찰 가능한 입력·정보 흐름·예산·판단 변경을 기록한다.

## 1. 입력 고정과 실험 식별

각 과제는 실행 전에 입력 패키지를 고정한다. 패키지에는 문제 서술, 첨부 자료, 외부 조회 허용 범위, 평가 질문, 종료 조건, 버전과 시각을 포함한다. 원문과 정규화된 표현의 SHA-256을 각각 기록하고, 실행 중 입력을 교체하거나 추가하지 않는다. 변경이 필요하면 새 과제 ID와 새 해시를 부여한다. 숨겨진 정답이 있는 과제는 정답을 사전에 판단 주체에게 공개하지 않고, 사후 평가용 별도 봉인 자료로 관리한다.

각 판단 주체에는 동일한 고정 입력만 제공한다. 초기 응답이 완료되고 저장되기 전에는 다른 주체의 응답, 투표, 합의, 평가자 의견을 공개하지 않는다. 완료 후에만 교환 단계를 열고, 공개 전 독립 판단과 공개 후 수정 판단을 별도로 저장한다.

## 2. 독립성의 정의와 문맥 격리

실제 독립성은 단순히 서로 다른 모델을 사용하는 것과 구별한다. 독립성은 최소한 (a) 공개 전 판단의 정보 비공유, (b) 주체별 상태·대화 문맥 분리, (c) 다른 주체의 산출물에 대한 접근 차단, (d) 동일한 외부 자료를 사용했는지에 대한 기록을 포함한다. 같은 모델을 별도 문맥에서 실행한 경우는 정보 비공유 독립성은 있지만 모델 수준의 다양성은 낮다. 서로 다른 모델을 사용해도 동일한 프롬프트·출처·검색 결과를 공유하면 공통 원인 편향을 가진다. 따라서 “독립 판단”과 “오판 원인의 독립”을 별도 변수로 보고한다.

문맥 격리는 계정·세션·캐시·검색 기록·도구 결과·재시도 상태를 포함한다. 격리가 확인되지 않은 실행은 독립 평가가 아니라 독립성 미확인 실행으로 표시한다. 완료 전 공개 금지 위반, 로그 누락, 입력 해시 불일치는 해당 쌍 또는 라운드의 독립성 판정에서 제외하고 사유를 기록한다.

## 3. 공통 오판과 근거 중복 관찰

모든 답변은 결론만이 아니라 해석, 핵심 근거, 가정, 반례, 불확실성, 추가로 필요한 관측을 구조화해 저장한다. 근거마다 출처 식별자와 인용 범위를 붙이고, 동일 문서·동일 검색 결과·동일 데이터 변환을 사용했는지 표시한다. 공통 오판은 답이 같다는 사실만으로 판정하지 않는다. 다음을 함께 비교한다.

- 같은 오류 명제 또는 같은 잘못된 전제를 채택한 주체 수
- 근거 출처 식별자의 중복률과 인용 구간의 중복률
- 오류가 같은 외부 출처·프롬프트 단서·모델 계열에서 유래했는지
- 판단 시점과 공개 후 수정 방향의 상관
- 정답이 알려진 과제에서 주체별 오류 벡터의 상관, 정답이 없는 과제에서 독립 전문가·후속 관측과의 불일치

관찰 지표는 평균 정확도만으로 통합하지 않는다. 주체 간 오류 상관, 근거 중복률, 공통 오류율, 고유 오류율, 공개 후 앵커링으로 인한 변경률, 독립 단계에서 형성된 고유 해석 수를 함께 기록한다. 작은 표본의 상관은 추정치로만 제시하고, 신뢰구간·표본 수·결측을 명시한다.

## 4. 비교군과 공정한 예산 계약

비교에는 최소 세 조건을 둔다. 단일 판단은 1개 답변, 단순 협의는 3개의 독립 답변을 투표로 집계하며, 경쟁 방식은 동일한 3개의 독립 답변을 유지한 뒤 별도 조정자가 검토한다. 이 공유입력 설계는 작은 파일럿의 **paired exploratory 분석**이다. 단일 1답, 단순 협의 3답, 경쟁 방식 3답은 호출 수와 검토 단계가 다르므로 equal budget 비교가 아니다. 따라서 이 결과로 비용 대비 우월성을 결론내리지 않는다.

엄격 비교에서는 조건별 모델 수, 최대 토큰, 도구 호출 수, 허용 시간, 외부 조회 범위, 조정자 호출 수, 저장·평가 비용을 사전에 동일하게 계약한다. 자원 차이가 있는 탐색 파일럿은 별도 보고하고, 무엇이 추가 자원인지 표시한다. 전자는 공정한 조건에서의 비교, 후자는 가능한 구조와 신호를 찾는 탐색으로 해석을 분리한다. 재시도와 실패 처리도 예산에 포함하며, 초과 시 결과와 중단 사유를 남긴다.

## 5. 유도 가설과 앵커링

가설을 제공한 조건과 제공하지 않은 조건을 분리한다. 유도된 가설, 후보명, 예시 답안, 조정자의 요약을 본 판단 전 제공하면 앵커로 기록한다. 공개 후 교환 라운드에서는 각 주체가 최초 판단을 보존한 상태에서 다른 답변을 본 뒤 수정하게 한다. 수정 전후를 비교해 최초 근거가 사라지고 다수 의견의 표현만 복제되는지, 반례를 추가하는지, 독립적 근거로 정당하게 변경하는지 관찰한다.

## 6. 재현성 메타데이터와 미확인 비용

각 실행에는 과제 해시, 실행 ID, 주체 ID, 모델·버전, 프롬프트 해시, 입력 출처, 문맥 격리 상태, 실행 시작·종료 시각, 토큰·호출·도구 사용량, 재시도, 지연, 실패, 공개 시점, 최초·수정 답변, 평가자와 판정 규칙을 기록한다. 실제 비용을 측정하지 못한 항목은 0으로 채우지 않고 “미확인”으로 남긴다. 특히 사람의 검토 시간, 검색 비용, 판단 변경에 따른 실행 비용, 운영 지연, 실패 복구 비용은 별도 계측 대상이다.

## 7. 판정과 보고

보고서는 사실, 관찰된 결과, 해석, 미검증 가설을 구분한다. 합의율이 높다는 사실을 정확성이나 독립성의 증거로 승격하지 않는다. 독립성 위반·입력 변경·예산 초과가 있으면 조건별 유효성 상태와 제외 사유를 명시한다. 결론은 유지·수정·기각·유보 중 하나와 그 근거를 제시하고, 다음 라운드에서 판정을 바꿀 관찰을 적는다. 이 프로토콜 자체도 파일럿 결과와 재현성 점검에 따라 개정하며, v0.1의 절차나 지표를 확정된 제품 아키텍처로 취급하지 않는다.
