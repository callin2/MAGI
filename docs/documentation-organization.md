# 문서 정리 기록

[문서 목차](README.md) · [이슈 #26](https://github.com/callin2/MAGI/issues/26)

## 후속 동기화 확인 — 2026-10-23

- 고객 결과: 다른 곳에서 진행한 작업을 먼저 반영한 뒤, 최신 연구와 문서 원문을 한 목차에서 찾는다. 이번 작업은 문서 정리의 후속이며 제품 개발이나 새 효과 실험으로 범위를 바꾸지 않는다.
- 확인한 결손: 이 체크아웃의 기본 fetch 설정은 main만 추적하므로 일반 fetch만으로 후속 연구 브랜치가 최신인지 보장되지 않는다.
- 다음 행동과 이유: 전체 원격 브랜치를 명시적으로 가져와 main·후속 연구·기존 문서 PR의 SHA를 비교하고, 이후 일반 fetch에도 전체 브랜치가 포함되게 로컬 설정을 고친다. 실험 자료는 유지하고 기존 목차·검증 안내를 갱신한다.
- 수용 증거: 원격과 로컬의 대응 SHA, 기존 문서 PR의 기반 브랜치, 목차·링크·ID·중복 검사, 실험과 스크립트의 Git 콘텐츠 보존을 확인한다. 중앙 shared-context/work-status 도구는 현재 제공되지 않아 이 기록에 unavailable 상태를 남긴다.

확인 결과: GitHub main은 `244c7c76624e086331ccf463d4b71c2912ecaf9e`, 후속 연구는 `017e18474d2482725a71f8c58cbee272e4750250`으로 기존 정리 기준과 같다. PR27은 해당 연구 브랜치를 기반으로 열려 있다. 연구·문서의 새로운 원격 변경을 놓치지 않도록 로컬 fetch 설정에 전체 heads를 추가했다. [동기화 확인 절차](verification.md#다른-pc의-작업을-가져온-뒤-문서-확인)를 실행 안내 한 곳에 기록했다.

관리 문서 21개·고유 ID 21개·로컬 링크 223개(헤딩 12개)의 검사가 통과했고 긴 문단 완전 일치 중복은 0건이다. 보호 파일 2,008개는 이전 감사와 같은 manifest이며 Git 콘텐츠 변경이 없다(원문 바이트 일치 435개, 기존 CRLF 변환만 있는 파일 1,573개). 감사 관측은 기존 JSON에 추가했으며 이전 결과는 보존했다. 연구를 재실행하지 않았다. main 병합과 다른 프로젝트 문서 전체 정리는 이 MAGI 정리의 완료 범위에 포함하지 않는다.

후속 변경은 [커밋 88c664b](https://github.com/callin2/MAGI/commit/88c664b8533d7903b22f45a1a5ad38840665a638)로 push했으며 [이슈 #26 검증 기록](https://github.com/callin2/MAGI/issues/26#issuecomment-6363702926)에 문서·검증·남은 범위를 연결했다.

## 결정 체크포인트

- 고객 결과: MAGI의 사용법, 현재 계약, 검증 결과와 미완료 제안을 한 목차에서 찾고, 같은 내용을 여러 문서에서 고치지 않아도 된다.
- 확인한 결손: README의 결과·명령이 보고서와 반복되고, 과거 계획의 현재형 표현이 후속 결과와 혼동된다. 전문성·기억 제안은 별도 브랜치에만 있다.
- 다음 행동과 이유: 기존 문서 경로를 유지하며 주제별 목차와 최소 front matter를 붙인다. 실행 안내는 한 문서로 합치고, 보고서는 당시 관측 기록으로 구분한다. 제안 문서를 기존 브랜치에서 가져와 연결한다.
- 수용 증거: 모든 관리 문서가 목차에서 연결되고 ID가 유일하며 로컬 링크가 유효하다. 실행 안내의 중복을 제거하고, 실험·스크립트의 Git diff와 보관 파일의 바이트 변경이 없어야 한다.

## 범위

현재 MAGI 작업 브랜치의 README와 docs, 그리고 기존 expertise-memory-review 브랜치의 제안 문서가 대상이다. 다른 프로젝트 문서를 MAGI로 옮기지 않는다. 실험 입력·응답·판정·실패 기록과 코드 복사본은 독립적인 증거이므로 중복 삭제 대상이 아니다.

중앙 shared-context MCP는 현재 제공되지 않아 조회·적용은 확인하지 못했다. 기존 fleet client로 이 작업의 시작 상태는 기록했다.

## 적용한 정리

- README의 반복된 결과표·수치·명령을 걷어내고 목적별 진입 링크로 바꿨다.
- [목차](README.md)는 질문별 진입, 계약, 연구 기록, 문서 관리 규칙을 제공한다. 모든 관리 문서에 고유 ID·유형·상태·소유 프로젝트·검토일·주된 이슈와 돌아오는 링크를 붙였다.
- 현재 실행 명령은 [실행·검증 안내](verification.md) 한 곳에서 관리한다. 검사 코드에서 쓰기 동작을 확인해 읽기 전용 검사와 결과 재생성을 구분했다. 보고서에는 당시 수치와 판정 이유를 남겼다.
- 초기 평가 계약의 낡은 “현재” 표현을 작성 당시로 한정했다. 학습 계획에는 후속 실행 링크와 제안/실행 조건 차이를 표시했다. 과거 계획을 완료된 실험으로 바꾸지 않았다.
- [전문성·기억 제안](expertise-memory-review.md)은 [기존 원문 커밋](https://github.com/callin2/MAGI/commit/daae5f4c63674d1d162e832f032c77511830a011)에서 가져왔다. 본문과 검토 중 상태를 유지했고 메타데이터·목차 링크만 정리했다. 원래 브랜치는 보존했다.
- 기존 파일 경로를 유지했다. 결과 점수, 계약의 실질 규칙, 실험·소스 파일은 변경하지 않았다. 프로젝트의 AGENTS.md에서 목차와 관리 규칙을 로드하도록 연결했다.

## 검증과 남은 범위

[검사 결과](documentation-audit.json)에 실제 관측 시각, 검사 대상 수, 링크·메타데이터 결과와 보호 파일의 manifest digest를 기록한다. README·AGENTS·관리 문서의 로컬 경로/헤딩 링크, 목차 포함과 고유 ID, 긴 문단의 완전 일치 중복을 검사하고 의미 중복은 변경 diff로 검토했다. 보호 대상은 추적되는 experiments/scripts 파일이며 Git diff가 없어야 한다. 실험의 점수나 결과를 재생성하는 스크립트는 실행하지 않았다.

문서 17개의 메타데이터·고유 ID·목차 연결, 관리 파일 19개의 로컬 링크 124개(헤딩 4개 포함)를 확인했다. 긴 문단의 완전 일치 중복은 0건이다. 추적된 실험·소스 파일 666개에는 Git 변경이 없으며 최종 checkout digest를 기록했다. 전문성 제안은 메타데이터와 추가한 탐색 링크를 제외하고 기존 본문과 일치한다.

이번 완료 범위는 MAGI 문서 정리다. 다른 저장소·다른 PC 문서 전체를 정리하거나 중앙 동기화한 것은 아니다. #23의 제안 검토와 #18/#19의 후속 효과 검증은 그대로 남는다. 변경은 [PR #25](https://github.com/callin2/MAGI/pull/25)에서 검토하며 main 병합 여부는 PR 상태를 따른다.

정리와 검증은 [커밋 c886bd9](https://github.com/callin2/MAGI/commit/c886bd9e5277736e08ba95374574760f75d311fa)에 보존했다. 이슈 #26에 같은 커밋과 검증 결과를 연결한다.

## 2026-10-23 GitHub 동기화 후 갱신

- 고객 결과: 다른 PC에서 추가한 연구까지 같은 문서 입구에서 찾고, 결과 원본·후속 해석 정정·main 병합 상태를 구분한다.
- 확인한 결손: 로컬 브랜치는 `d2769ab`에 머물렀고 README는 10월 18일 보고서를 최근 결과로 안내했다. 이후 두 비교가 연구 순서표에서 빠졌으며 별도 INDEX가 같은 파일 목록을 중복 관리했다.
- 다음 행동과 이유: 전체 원격 브랜치를 가져와 기존 작업의 후손인 `017e18474d2482725a71f8c58cbee272e4750250`을 기준으로 `codex/docs-sync-20261023`을 만들었다. 기존 브랜치를 보존하고 목차·실행 안내만 갱신한다. 최신 보고서의 sealed 경계 해석 정정과 고정 원점수는 그대로 유지한다.
- 통과 증거: 문서 ID·로컬 경로/헤딩·목차 연결 검사, 긴 문단 중복 검사, 기준 커밋 대비 experiments/scripts 및 세 후속 보고서의 Git 콘텐츠 무변경을 확인한다. Windows checkout의 줄바꿈 차이는 바이트 일치와 별도 계수하며 원본을 재작성하지 않는다. 과거 실험을 다시 생성하거나 채점하지 않는다.

GitHub 확인 당시 MAGI에는 dev 브랜치가 없고 main은 `244c7c76624e086331ccf463d4b71c2912ecaf9e`다. 기존 PR #25는 열려 있다. 이후 연구는 `codex/cross-system-transfer-20261019`, `codex/cross-system-three-models-20261019`, `codex/hard-domain-transfer-20261019`에 있다. 이 동기화는 후속 연구 브랜치를 로컬에서 사용하는 것이며 main 병합이나 제품 배포가 아니다.

README는 최신 보관 연구로 연결하고, 주제별 목차에 후속 연구 순서와 해석 정정을 추가했다. `docs/INDEX.md`는 호환 경로를 유지하는 안내로 줄여 두 목차를 따로 갱신하는 중복을 없앴다. 실행 안내에는 후속 실험의 원문 링크와 읽기/쓰기·플랫폼 경계를 추가했다. 결과 수치나 명령 전체를 다른 곳에 복제하지 않았다.

중앙 shared-context/work-status MCP는 이 세션에 제공되지 않았다. 중앙 보고·적용 완료를 주장하지 않는다. 검증 결과는 기존 [감사 파일](documentation-audit.json)에 후속 관측으로 추가하며 10월 18일 기록은 유지한다. 연구 #18/#19와 main 병합은 여전히 별도 미완료 범위다.

검증 결과: 관리 문서 21개의 ID와 메타데이터, 관리 파일 23개의 로컬 링크 220개(헤딩 11개), 목차 연결이 통과했다. 긴 문단 완전 일치 중복은 0건이다. 보호 파일 2,008개 중 435개는 Git 원문 바이트와 같고, 1,573개는 기존 Windows checkout의 CRLF 변환만 다르다. Git 콘텐츠 변경은 없으며 checkout manifest hash를 보존했다. 최초 엄격한 바이트 검사의 실패와 줄바꿈 원인을 감사 파일에 남겼다. 실험 실행·채점·원본 파일 재작성은 하지 않았다.

문서 변경은 [커밋 3377445](https://github.com/callin2/MAGI/commit/3377445bf31976c61b4bf8b5d88571c9865e27bd)로 push했다. [#26 검증 기록](https://github.com/callin2/MAGI/issues/26#issuecomment-6363047888)과 [후속 연구 브랜치 대상 PR27](https://github.com/callin2/MAGI/pull/27)에서 확인한다.
