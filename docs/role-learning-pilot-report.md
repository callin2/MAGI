# 역할 경험 지속·전이 실행 결과 — #10, #13~#18

2026-10-16. 조사·계약·최소 구현·실제 LLM 탐색 실행을 수행했다. **지속/조회 경로는 동작했지만 정제 교훈의 독립적 우월성과 토큰 효율은 입증하지 못했다.**

- #10: [기존 사례 비교·재사용·협업 레시피](learning-precedents.md)를 작성했다. 공개 문서, 고정 ACE 소스의 확인 범위, 원저자 실험, 직접 시험을 구분했다.
- #13~#15: [세 독립 가설 경쟁 평가](../experiments/role-learning/design/)가 모두 완료된 뒤 [계약과 조정 근거](role-learning-contract.md)를 기록했다. 역할 상태 범위와 provisional 적용에 대한 이견을 보존했다.
- #17을 선등록한 뒤 Python 표준 SQLite와 git, 기존 에이전트 실행을 조합하는 작은 adapter를 구현했다. 특정 제품을 새로 설치하거나 전체 기억 프레임워크를 다시 만들지 않았다.

## 구현과 검증

`scripts/role_memory.py`는 JSON 요청을 받아 SQLite 상태를 처리한다. 역할/version·project·agent binding, 경험/후보, 검증·보류·철회, private/role 범위, 버전 고정 grant, 충돌의 조회별 보류, stale receipt 거부와 변경 전후 이력을 제공한다. 새 프로세스마다 디스크 상태를 다시 연다.

별도 코드 검토에서 binding의 역할·프로젝트 확인, grant 버전 참조, 변경 전후 이력, 같은 state의 비소유 agent 쓰기 권한을 보완했다. 충돌은 조건별 조회에서만 보류하도록 계약을 명확히 했다. 원문 active 상태까지 전역 변경하지 않는다.

실패 지향 통합 시험 7개가 통과했다. 모든 adapter 연산은 새 프로세스다. 새 agent 승계와 private 제외, 후보/value/불충분 근거 차단, grant/ungrant/철회, 조건 변경·해제·버전 불일치, 수정 version과 공유 재승인, 충돌 보류, 타 state와 private source 확대 거부를 포함한다. 토큰·실사용 성과 시험과 구분한다.

검증 기록의 형식 검사는 외부 근거의 진위를 증명하지 않는다. API 범위 검사는 OS sandbox가 아니다. 의미 충돌 자동 발견과 임의 코드/모델의 무단 파일 접근 방지는 구현하지 않았다.

## 사전 고정과 실제 실행

[프로토콜](../experiments/role-learning/pilot/protocol.md), 사례/정답 키·경험 로그·해시는 첫 학습/판단 호출 전에 고정하고 #16에 게시했다. 새 agent는 `fork_turns=none`으로 생성했고 자신의 입력 파일만 읽었다. 이전 대화·타 조건의 의견·정답 키는 제공하지 않았다. 모델/설정은 동일하게 상속했고 작업·역할 수를 제품 구조로 고정하지 않았다.

합성 Delta 사례는 원격 부모 ID, 세션을 넘어 유지되는 중복 방지 키, 빈 페이지의 다음 cursor라는 기술 경험이다. 전이 과제는 다른 ID/작업을 사용하며, 다른 시스템/version은 기존 교훈 적용 범위 밖 대조다. 어려운 신규 사업 판단이나 실제 수 주 협업을 대표하지 않는다.

고정된 작업 종료 reflection이 명시적 새 ‘기억해’ 요청 없이 후보 3개를 생성했다. 이는 지시된 학습 절차이며 자발적 가중치 학습을 의미하지 않는다. 조정자가 규칙을 직접 작성하거나 정답에 맞춰 고치지 않았다. source 대조와 실행된 조건 필터 시험을 근거로 delta v1에 한정해 활성화했다. 실제 API 검증이나 일반화 증거라고 주장하지 않는다.

## 결과: 주 시험 4과제 × 2반복

| 조건 | 요구 필드 그대로의 엄격 정답 | 형식을 해석한 보조 진단 | 재설명 요청 출력 |
|---|---:|---:|---:|
| 기억 없음 | 3/8 | 3/8 | 5/8 |
| 원문 로그 | 8/8 | 8/8 | 0/8 |
| 정제 교훈 | 5/8 | 8/8 | 0/8 |

보조 진단은 사후 설명이며 엄격 점수를 대체하지 않는다. 정제 교훈 2회차에서 3개 필드를 최상위가 아닌 `required action fields` 아래에 넣었다. 조정자가 만든 “required action fields”라는 출력 지침의 모호함이 영향을 주었다. 원문을 수정하지 않고 엄격 점수에서는 실패로 보존했다. 기억 없음 1회차는 명시된 다른 시스템의 현재 계약도 적용하지 못했다. 이 오류도 그대로 남겼다.

재설명 요청은 모델의 `need_clarification` 출력 수이며 실제 인간의 설명 횟수나 시간 절감이 아니다. 기억 없음은 더 적은 정보를 받으므로 정보량을 맞춘 추론 능력 비교도 아니다. 원문 로그와 정제 교훈 모두 의미상 정답이었고, 이 크기의 시험에서 정제의 독립 이득은 확인되지 않았다.

## 교훈 제외·철회 대조

pagination 교훈을 제외한 새 worker와 철회 뒤 새 worker는 교훈 ID를 쓰지 않고도 continue를 선택했다. 이 판단은 기초 모델 추론으로도 가능하므로 “교훈을 사용했다고 응답했기 때문에 그 교훈이 성과를 만들었다”는 설명을 지지하지 않는다.

제외 대조의 입력 snapshot을 만든 뒤 원본 상태에서 철회가 발생했다. 따라서 제외 대조는 고정 입력에 대한 응답 진단이며, 현재 상태의 적용 영수증으로는 stale여서 4/4 거부됐다. 철회 후 새로 조회한 4/4 영수증은 수용됐고 해당 교훈은 모두 제외됐다. 과거 노출을 모델이 잊었다고 주장하지 않는다. 다음 실험은 별도 상태 분기로 ablation 적용 경로까지 고정해야 한다.

## 비용과 해석 한계

기억 생성 1회, 주 시험 6회, 제외/철회 2회로 9개의 실질 LLM 실험 턴을 수행했다. 설계 평가 3회와 구현 검토 2회까지 합치면 실질 child turn은 14회다. 원문 저장을 위한 child 후속 턴 12회도 추가 비용이다. 이는 provider 내부 모델 호출 수가 아니며, 주 에이전트·도구 처리·각 턴 내부 호출도 별도로 존재한다.

현재 협업 도구는 전체 입력/출력 token·청구 비용을 노출하지 않는다. 총 token, 비용, 전체 model call 수는 unknown이다. 입력 문자/바이트와 영수증은 저장했지만 token으로 환산하지 않는다. 1회차 타이머는 수집하지 못했고, 2회차는 dispatch/완료 관측 시각만 남아 원문 저장·조정 시간이 섞였다. 모델 생성 지연이나 총 작업시간으로 표시하지 않는다. 동일 총예산 우월성·토큰 절감·장기 학습 효과를 주장할 근거가 없다.

동일 모델·작은 유도된 합성 사례·반복 2회·조건별 묶음 실행·정제 검증자의 source 검토·출력 계약 모호함의 한계가 있다. 실제 행동은 JSON 판단 출력과 adapter 적용 기록까지 확인했으며 외부 업무 완료는 검증하지 않았다.

## 이슈 처리와 후속

#10과 #13~#15는 조사·계약 정의 근거로 완료했다. #17은 작은 구현·계약 시험 범위로 완료한다. #16은 탐색 실험 결과를 기록하되 총비용·실제 업무 효과 검증이 남아 OPEN으로 유지한다. #11도 전체 완료 처리하지 않는다.

남은 작업은 별도 지시를 기다리지 않고 #18에 등록했다: 모든 조건의 기계 판독 출력 스키마 고정, 실제 사용량을 제공하는 실행 경로, 더 현실적인 협업 과제, 상태 분기의 교훈 제외·오염·철회, 총비용을 포함한 확대 비교. 아직 수행하지 않은 확대 검증을 완료로 표시하지 않는다.

```sh
python3 scripts/test_role_memory.py -v

```

둘 다 새 모델 호출을 하지 않는다. 첫 명령은 실제 임시 DB/새 프로세스에서 계약을 시험하고, 두 번째는 고정 해시·영수증·원문 응답과 점수를 확인한다. `prepare_role_learning.py /absolute/path/new-state.sqlite`는 비어 있는 DB에 저장된 후보와 사건을 재생하고 입력을 만든다. 기존 실험 산출물을 다시 쓸 수 있으므로 별도 checkout에서 실행한다. 새 LLM 응답은 현재 도구로 별도 실행해야 하며 저장된 답을 새 실행이라고 보고하지 않는다.
