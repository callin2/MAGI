# MAGI 실제 효과 검증 — 2026-10-18

관련 업무: [#18](https://github.com/callin2/MAGI/issues/18), [#19](https://github.com/callin2/MAGI/issues/19).

검토 제출: [PR #25](https://github.com/callin2/MAGI/pull/25). [사전 등록 6523f77](https://github.com/callin2/MAGI/commit/6523f77), [입력 바이트 보존 9e7ea72](https://github.com/callin2/MAGI/commit/9e7ea72), [결과·비용·실패 기록 35cde0f](https://github.com/callin2/MAGI/commit/35cde0f). main 병합 전 상태다.

**결론: 실제 코드 수리에서 과거 경험 전달의 유용성 신호를 관찰했다. 그러나 풍부한 정제 교훈 E는 같은 경험을 짧은 규칙으로 전달한 F보다 추가 성공을 만들지 않았고, 처리 토큰은 더 많았다. MAGI 전체의 학습·다중 협의·전문가 라우팅 효과와 인간 시간 절감은 여전히 미입증이다.**

## 결정 체크포인트

고객 결과 → 에이전트에게 맡긴 실제 업무에서 과거 경험이 반복 오류와 재설명을 줄이고, 비용을 감수할 가치가 있는지 판단한다.

관측된 간극 → 기존 새 세션 실험은 도구 계약을 고친 뒤 G/F/L/E 모두 17/17이었다. 기억 자체의 효과와 전체 비용은 미입증이다. 이번 소스 점검에서 `init`은 `done, evidence=[]` 상태를 받아들였다. 이는 `complete`가 거부하는 상태다. Windows 임시 디렉터리에서 실제 재현했으며 제품 DB와 관계없다.

다음 행동 → 기존 tracker와 역할 기억 adapter, 실제 실패·교정에서 이미 추출한 교훈을 재사용한다. 새로운 코드 수리와 새 검토 자료 작성 두 업무에서 독립 실행을 비교한다. 실험 도구 설명·입력·판정·중단 기준을 모델 실행 전 고정한다.

수용 증거 → 원본 실패, 각 실행의 도구 호출·파일·상태·기억 receipt·측정 가능한 usage, 사전 고정 판정 및 실패를 모두 보존한다. 통과한 코드 후보는 별도 리뷰 후 기존 소유 모듈에 반영한다. 실험 통과를 MAGI 전체의 우월성으로 확대하지 않는다.

## 사전 고정 비교

- G: 과거 경험 없음. 현재 요청, 필수 제약, 현재 자료, 도구 계약은 모두 동일.
- F: 기존 교훈의 rule/conditions만 고정 지침으로 제공.
- L: 실제 관측 이벤트 원문 제공.
- E: 기존 adapter가 조회한 조건부 교훈 제공.
- A: 해당 업무와 가장 관련 있는 교훈 제외.
- C: 해당 교훈을 의도적으로 잘못된 내용으로 바꾼 오염 탐침. 실제 기억 저장소에는 채택하지 않는다.
- R: 기존 adapter에서 해당 교훈을 철회하고 새 receipt로 조회.

주 비교는 두 업무 × G/F/L/E × 2회 = 16회. A/C/R은 각 업무 1회씩 6회로 총 22회. 탐침은 방향 확인용이며 효과 크기 추정에 합산하지 않는다. 고정 seed로 실행 순서를 섞고 매번 새 대화·별도 파일 상태로 시작한다. 모델에게 평가 키, 다른 조건의 결과, 이전 대화를 주지 않는다. 임의의 AGENTS/확장/MCP/도구 검색도 로드하지 않는다.

코드 업무는 기존 tracker의 import 완료 상태 검증을 고치고 회귀 시험을 작성한다. 문서 업무는 현재 공개 소스와 검토 제안으로부터 사용자가 받을 수 있는 것과 다음 할 일을 구분한 인계 자료를 만든다. 두 업무 모두 실제 파일 생성과 기존 tracker의 작업·근거 완료를 요구한다. 파일 존재와 해시는 내용의 정당성과 별도로 검사한다.

요청·schema·판정 코드·기존 소스·교훈·실행 순서의 SHA-256은 `experiments/effectiveness-20261018/frozen.json`에 고정한다. 모델은 기존 Pi 연결의 `atomic-8317/gpt-6-luna`를 전 조건에서 사용한다. 이는 서버가 제공한다고 응답한 모델 이름이며 내부 가중치는 검증하지 않는다. bounded 반복 작업은 저비용 모델을 쓰라는 사용자 원칙을 적용한다. client reasoning parameter는 보내지 않아 서버 기본값이다.

사전 점검에서는 실험 실행기의 timeout 소수점 오류, 그리고 Pi에 등록됐지만 서버가 제공하지 않는 `gpt-5.5-medium` 오류가 각각 발견됐다. 모두 기록을 보존했다. 실제 `/models` 목록을 조회해 `gpt-6-luna` 지원을 확인했고, 기존 연결에서 호출 모델 ID만 바꾼다. 사용자의 Pi 설정 파일은 수정하지 않는다. 이는 본 실험 입력·결과 생성 전에 결정했다.

각 실행은 모델 응답 최대 16회, 도구 60회, 5분, 응답당 최대 8,192 output token으로 제한한다. 자동 재시도·대화 압축·사후 교정 프롬프트는 없다. 전송 장애는 해당 실행 실패로 보존하며 두 번 연속 전송 장애면 공급자 상태를 조사하고 남은 실행을 중단한다. 응답 timeout은 실행 중지 여부를 확인한 뒤 처리한다. 실패를 없애려고 같은 실행을 다시 생성하지 않는다.

전체 성공 = schema + 숨겨진 업무 판정 + 실제 파일/hash/tracker 완료 + 기존 회귀 유지. 각 축과 최초 실패/복구도 따로 보고한다. 실행 후 평가 오류가 발견되면 원평가를 보존하고 영향받은 비교를 무효 표시한다. 코드 업무에는 정상 완료 import와 변경된 증거를 reopen할 수 있는 반례를 포함해 과잉 거부를 검출한다.

usage는 제공자가 반환한 input/output/cache 수치를 보존한다. proxy의 0 가격을 무료라고 해석하지 않는다. 기존 교훈 생성·사람 리뷰 시간과 이번 조정자의 전체 비용은 관측 불가하면 unknown으로 남긴다. 따라서 이번 실행 단계 비용을 전체 생애 비용으로 부르지 않는다. 사람의 시간 절감, 다른 모델/프로젝트 일반화, 다중 협의 자체의 추가 이득은 이번 비교가 입증하지 않는다.

공유 작업 현황은 기존 fleet client로 현재 native session에 등록했다. `work_status`/`shared_context` MCP는 이 세션에서 제공되지 않아 중앙 공유 원칙의 새 조회·적용 증명은 unavailable이다. 실험이 새로운 상태 서버나 개발 DB를 만들지는 않는다. SQLite 파일은 기존 MAGI adapter의 재현 가능한 실험 fixture다.

## 실행 결과

Windows에서 **22/22 실행을 완료**했다. 사전 프로토콜의 불변 원본은 [preregistration.md](../experiments/effectiveness-20261018/source/preregistration.md), 원점수는 [results.json](../experiments/effectiveness-20261018/results.json), 집계는 [summary.json](../experiments/effectiveness-20261018/summary.json)에 둔다. 모든 실행이 정해진 한도 안에서 종료했고, 결과가 나쁜 실행을 새 응답으로 교체하지 않았다.

| 조건 | 코드 수리·완료 | 인계 문서 strict 판정 | 주 비교 합계 | 4회 처리 토큰 합계¹ |
|---|---:|---:|---:|---:|
| G 과거 경험 없음 | 0/2 | 1/2 | 1/4 | 423,018 |
| F 과거 교훈의 짧은 규칙/조건 | 2/2 | 2/2 | 4/4 | 340,286 |
| L 실제 관측 원문 로그 | 2/2 | 1/2 | 3/4 | 470,698 |
| E 조건부 교훈·근거·메타데이터 | 2/2 | 2/2 | 4/4 | 441,115 |

¹ 제공자가 반환한 input + output + cache read/write의 누계다. 캐시를 포함하므로 유료 토큰이나 현금 비용과 같지 않다. 가격 설정 0을 무료로 해석하지 않았다.

코드 과제에서 G의 두 실행 모두 없는 status를 open으로 간주한 뒤 원래 JSON에는 status를 넣지 않아 기존 평가기도 거부하는 상태를 저장했다. F/L/E는 각각 2/2 통과했다. 이 차이는 필요한 경험 전달이 도움이 될 가능성을 보이지만, 한 저장소의 두 업무·조건별 2회로 일반적인 인과 효과를 입증하지 않는다.

E는 F와 같은 통과 수를 얻었지만 주 비교 4회 처리 토큰 합계는 **29.6% 더 많았다**. 코드만 보면 평균 처리 토큰은 176,574 대 126,843.5로 39.2% 많았고, 실행 시간은 약 190.7초 대 131.3초였다. 인계 문서에서는 E가 약 38.9초, F가 44.1초로 더 빨랐으므로 모든 작업에서 느렸다고 일반화하지 않는다. 시간에는 공급자 부하·네트워크·캐시·도구 변동이 포함된다.

F도 과거에 실제로 추출한 교훈에서 rule/conditions를 가져왔다. **F는 ‘학습 없이 처음부터 주어진 일반 지침’이 아니라 같은 경험의 짧은 표현 대조군**이다. 실험 fixture 준비에는 동일한 기존 adapter를 사용했다. 따라서 이 비교는 worker에 어떤 경험 내용을 전달할지에 관한 결과이며, 지속 저장·갱신·조회 시스템 전체가 불필요하다는 검증이 아니다.

문서 자동 판정은 상태 라벨 정의가 충분히 명확하지 않았다. r003의 `experimental/unproven`, r009와 r019의 `unproven/planned` 차이는 원판정에서 실패지만 실제 본문은 구현과 목표, 인과 효과 미입증을 정확히 구분했다. **이 라벨 차이를 경험 기억의 실제 효과로 계산하지 않는다.** [사후 내용 검토](effectiveness-semantic-review-20261018.md)에서 인계 문서 11개 모두 이 범위의 실질적 과장은 발견하지 못했다. 이 검토는 조정자 자신의 사후 검토이며 blind independent 평가가 아니고 원점수를 변경하지 않는다.

## 제외·오염·철회와 실제 실패

전체 strict 판정은 **16/22**다. 실패 6개는 상태 라벨 모호성 3개, 코드 상태 검증 누락 2개, 실제 tracker 완료 실패 1개로 구분된다.

- A 제외: 0/2. 문서는 라벨 차이였고, 코드는 시험을 통과했지만 해시 전사 오류를 반복해 child/root가 열린 채 끝났다. 미완료를 인정했으므로 허위 완료와도 구분한다.
- C 오염: 2/2. 해당 교훈의 rule만 잘못 바꿨지만 현재 요청/근거를 우선해 결과를 만들었다. 소규모 명시적 충돌 탐침이며 일반 오염 내성을 입증하지 않는다.
- R 철회: 2/2. 기존 adapter에서 실제 revoke 후 새 receipt를 조회했으며 대상 교훈이 빠진 것을 확인했다. 이미 그 교훈을 본 같은 대화에서의 기억 철회를 시험한 것은 아니다.

A와 R의 worker 입력은 각 업무에서 task/memory byte hash가 동일하다. 그러나 코드 A는 완료에 실패하고 R은 통과했다. 저장 이력·revision 차이는 worker에게 제공하지 않았으므로, 이 차이를 철회의 인과 효과나 특정 교훈의 필수성으로 해석하지 않는다. 원문과 진단은 [내용 검토](effectiveness-semantic-review-20261018.md)에 연결했다.

## 실제 수행량과 검증

22개의 새 도구 대화에서 모델 요청 **211회**, 도구 호출 **255회**, 도구 오류 **6회**를 기록했다. worker 실행 누계는 **2,290.1초(약 38.2분)**다. 제공자가 반환한 usage는 input 391,675, output 102,032, cache read 1,788,032로 합계 **2,281,739 token**이다. 연결 사전 점검의 성공 smoke 1,192 token과 조정·리뷰·과거 교훈 생성 비용은 이 숫자에 포함하지 않는다. 조정자 전체 비용, 과거 생성/검토 비용, 가격, 인간 시간, 전체 생애 비용은 **unknown**이다.

고정 입력·기억 receipt·제외/철회/오염 처리·새 대화·호출 수·한도를 검증한 [무결성 검사](../experiments/effectiveness-20261018/integrity.json)는 **274/274 통과**했다. 이는 자료/실행 일치성 검사이며 성공률이나 학습 효과 점수가 아니다. 사전 판정기 자체의 실패 지향 시험 5개도 통과했다.

발견된 실제 코드 결함은 [#24](https://github.com/callin2/MAGI/issues/24), [수정·검증 기록](tracker-import-validation.md), [커밋 a9a9b35](https://github.com/callin2/MAGI/commit/a9a9b35)로 연결했다. 코드 후보의 원출력과 소유 모듈에 최소 변경으로 통합한 수정은 분리했다. 원본 포함 회귀 32개와 별도 import 판정 13개가 통과했으며 main 병합은 아직 하지 않았다.

Windows 증거 저장의 줄바꿈 문제와 자동 승인 검토 후 수행한 전체 대조는 [바이트 보존 기록](../experiments/effectiveness-20261018/byte-storage-note.md)에 남겼다. 고정 입력/교훈/평가 기준을 변경해 실패를 없애지 않았다. 기존 자료의 원보고서도 보존한다.

## 적용 범위와 다음 판단

현재 구현의 실제 학습 경험을 제공한 **서로 이력이 없는 도구 대화**를 비교한다. 입력 분리·허용 파일 도구·별도 tracker/기억 fixture를 사용한다. 생성된 Python 시험은 일반 프로세스에서 실행되므로 OS 보안 sandbox를 검증했다는 의미는 아니다. retrieval receipt는 전달 사실을 증명하며 모델 내부에서 어떤 이유로 판단했는지 증명하지 않는다.

현재 결정은 **다음 비교의 기준선을 짧은 경험 규칙 F로 유지**하고, 풍부한 교훈 메타데이터를 항상 주입하는 방식을 효과가 입증된 개선으로 취급하지 않는 것이다. 필요한 경험을 선택하고 갱신하는 지속 기억의 운영 가치는 별도 검증 대상이다. 사용자의 운영 설정이나 전역 기억 정책을 변경하지 않았다.

남은 검증은 다음처럼 한정한다. #18에는 명확한 enum 의미, 다른 실제 업무/프로젝트에서의 반복, 학습·검토·조정 포함 비용을 남긴다. #19에는 해시 오타 뒤 끝까지 복구하는 행동, 타 작업 전이, 다중 협의의 동일 예산 비교를 남긴다. 전문가 라우팅은 #23의 검토 범위이며 이번에 구현하거나 효과를 검증하지 않았다. 사람의 재설명·시간 절감은 실제 측정 전까지 미입증으로 유지한다. 상위 이슈를 이번 22회 실행만으로 닫지 않는다.

## 자료 재확인

모델 호출 없이 보관 자료를 확인한다. Windows에서는 UTF-8 모드를 명시한다.

```sh
python -X utf8 scripts/effectiveness/verify_evidence.py
python -X utf8 scripts/effectiveness/evaluate.py
python -X utf8 scripts/effectiveness/summarize.py
```

`evaluate.py`는 저장된 후보 코드의 시험을 다시 실행하며 원래 실패도 재현한다. `collect.py`는 이미 채점한 실행을 재시험하지 않고 집계한다. `prepare.py`는 기존 frozen 자료를 덮어쓰지 않고, `run.mjs`는 완료된 실행을 재생성하지 않는다. 새 연구는 새 실험 식별자와 사전 등록을 사용해야 한다.
